## 설계 5원칙

| # | 원칙 | 해결 |
|---|------|------|
| 1 | **회사 돈과 고객 돈을 분리한다** | 예치금을 부채로 별도 집계, `실제 사용가능 자금` 자동 산출 |
| 2 | **주문번호가 기준이다** | `ORDER-2026-000001` 아래 입금·지출 N:M 연결 → 거래 단위 마진 |
| 3 | **입금 한 건을 성격별로 쪼갠다** | 매출 / 부가세 / 예치금 — 누구 돈인지로 나눠 저장 |
| 3-1 | **지우지 않는다** | 삭제 대신 취소, `이전값→변경값→수정자→수정시각→사유` 이력 |
| 4 | **환율은 데이터다** | 수식에 숨기지 않고 건별 컬럼으로 저장 |
| 5 | **세무처리는 설정값** | `거래유형` 설정으로 대상금액·부가세 방식 관리 (하드코딩 금지) |
| 6 | **부가세도 남의 돈이다** | 받은 부가세는 국세청에 낼 돈 → 사용가능 자금에서 차감 |

## 🔴 짚어드릴 점

세금계산서를 발행하지 않고 받은 부가세가 **92,574,600원**(369건)입니다.
받은 부가세는 신고·납부 의무가 따르고 미발행은 별도 문제가 될 수 있으므로, **세무사와 확인해 보시기를 권합니다.**
프로그램은 세무 판단을 하지 않고 집계와 목록(`세금계산서 관리 > 미발행·부가세 수취` 탭)만 제공합니다.
