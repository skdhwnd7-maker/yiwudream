# 이우드림무역 자금·정산 관리 시스템

중국 구매대행 업무의 **매입 / 매출 / 중국지출 / 해외송금 / 마진 / 세금계산서**를
관리하는 사내용 웹 시스템입니다.

> **완성.** 네 루트의 거래 등록부터 자금현황·세금계산서·대시보드·엑셀 이관·권한까지
> 전부 동작합니다. 자동 검증 281건이 모두 통과합니다 (`npm run verify`).
> 실제 엑셀 파일(1,100여 행)로 이관을 끝까지 돌려 보고 되돌려 봤습니다.

---

## 빠른 시작

```bash
# 1. PostgreSQL 준비 (16 이상)
createdb yiwudream

# 2. 환경변수
cp .env.example .env
#   DATABASE_URL  접속 정보
#   AUTH_SECRET   openssl rand -base64 32 로 생성한 32자 이상 문자열
#   COOKIE_SECURE HTTPS로 서비스하면 true, 사내망 http면 false

# 3. 설치 · 스키마 · 보호장치 · 기준정보
npm install
npm run db:push                       # 테이블 생성
npm run db:guards                     # 원장 불변·합계 검증 트리거
npm run db:seed                       # 거래유형·비용분류·계좌·관리자 계정

# 4. 실행
npm run dev                           # http://localhost:3000
```

화면을 먼저 둘러보고 싶으시면 시연 데이터를 넣을 수 있습니다.

```bash
npm run db:demo                       # 네 루트·부가세·미수금·중국 운영비 시연 데이터
npm run db:reset-demo                 # 전부 비우고 기준정보 + 시연 데이터 재생성 (개발용)
```

실제 엑셀은 화면에서 넣으십시오 — **관리 > 엑셀 가져오기**.
올린다고 바로 들어가지 않고, 무엇이 어떻게 들어갈지 대조표로 먼저 보여 드립니다.

초기 계정은 `admin` / `yiwudream1234` 입니다. **첫 로그인 후 반드시 바꾸세요.**
(`SEED_ADMIN_PASSWORD` 환경변수로 시드 시점에 지정할 수도 있습니다.)

## 검증

```bash
npm run verify      # 281건 자동 검증 (계산·원장·자금·세무·대시보드·이관·권한)
npm run typecheck
npm run build
```

`npm run verify`는 설계 문서가 약속한 것들이 실제로 동작하는지 확인합니다.

- 부가세 계산이 엑셀 실측값과 일치하는가 (법인통장 3,456,960 = 3,142,691 + 314,269)
- 환율 환산이 엑셀 수식과 일치하는가 (`=C6/218` → 14,416.02)
- 마진율 분모가 매출인가 (엑셀은 지출로 나누고 있었다)
- 거래처명 정규화가 표기 흔들림을 흡수하는가
- **예치금 원장과 변경이력을 고치거나 지울 수 없는가**
- **입금 분해 합계가 입금액과 다르면 저장이 막히는가**
- **정산완료된 주문에 전표를 못 넣는가**
- 자사(이우드림) 거래가 매출·마진·순위에서 빠지는가
- 입금 없는 주문이 마진을 적자로 만들지 않고 「미청구」 로 따로 잡히는가
- 엑셀 수식에서 꺼낸 환율이 헤더에 적힌 값이 아니라 실제 값인가
- 이관 배치를 되돌리면 그 배치가 만든 것만 사라지는가
- **직원 권한으로 회사 마진과 통장 잔액이 보이지 않는가**
- 화면에 적힌 권한 설명이 실제 권한과 맞는가

## 설계 원칙

| # | 원칙 | 구현 위치 |
|---|------|----------|
| 1 | 회사 돈과 남의 돈을 분리한다 | `ReceiptSplit.splitKind` — 매출/수수료/**부가세**/예치금 |
| 2 | 주문번호가 정산 단위다 | `Order` ← 입금·지출·송금 N:M |
| 3 | 지우지 않는다 | `deposit_ledger`·`change_logs` 불변 트리거 |
| 4 | 환율은 데이터다 | `Receipt.fxRate` — 수식에 숨기지 않는다 |
| 5 | 세무처리는 설정값 | `DealType` — 설정 화면에서 바꾼다 |

금액은 전부 `NUMERIC(18,2)` + `Decimal.js`입니다. 부동소수점 연산을 쓰지 않습니다.
금액 계산은 `src/lib/money.ts` 밖에서 하지 않습니다.

모든 금액성 수정은 `src/lib/audit.ts`의 게이트를 통과해야 하며,
사유 없이는 저장되지 않는 필드가 정의돼 있습니다.

### 권한

대표님 지시로 확정: **대표는 모든 것, 직원은 입력만.**

| 기능 | 대표 | 매니저 | 직원 | 조회 |
|------|:----:|:------:|:----:|:----:|
| 거래 목록·상세 조회 | ● | ● | ● | ● |
| 거래 등록·수정 | ● | ● | ● | |
| 거래처 등록·수정 | ● | ● | ● | |
| **회사 손익·자금현황** | ● | ● | | |
| 거래 취소 · 해외송금 · 세금계산서 · 급여 · 변경이력 | ● | ● | | |
| 설정·사용자 관리 · 엑셀 가져오기 | ● | | | |

- 권한은 **아이디를 만들 때 대표님이 고릅니다.** 고르면 그 권한이 무엇을 할 수 있고
  무엇을 못 하는지 그 자리에서 바로 보여 드립니다.
- 직원이 보는 첫 화면은 손익이 아니라 「이번 달 내가 입력한 것」 과 「챙길 것」 입니다.
- 메뉴는 권한에 맞춰 숨깁니다 — 보이는데 눌러도 안 되는 화면을 만들지 않습니다.
- **누가 무엇을 언제 고쳤는지는 권한과 상관없이 전부 변경이력에 남습니다.**
