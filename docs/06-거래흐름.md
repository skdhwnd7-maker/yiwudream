## 시나리오 A. 해외송금 — 지출이 여러 번 나뉜 경우

**실제 데이터**: 코러스 코리아 (해외송금 시트 4·5·22·33·79행)

| 엑셀 행 | 일자 | USD | CNY 도착 | CNY 지출 | 인건비 | 엑셀 마진 | 엑셀 % |
|--------:|------|----:|--------:|--------:|-------:|---------:|-------:|
| 4 | 05-05 | — | — | 8,384.00 | — | −8,384.00 | −100% |
| 5 | 05-05 | — | — | 3,726.00 | — | −3,726.00 | −100% |
| 22 | 05-11 | — | — | 2,066.90 | — | −2,066.90 | −100% |
| 33 | 05-14 | — | — | 11,540.00 | — | −11,540.00 | −100% |
| 79 | 05-29 | 5,918.88 | 39,733.00 | 36,007.90 | 1,809.00 | 1,916.10 | 5% |

**엑셀에서는** 4행이 별개 거래로 보여 −100% 마진이 네 번 찍힙니다.

### 시스템 처리

| 단계 | 업무 | 데이터 |
|------|------|--------|
| 1 | 새 거래 등록 → 코러스코리아 / 해외송금 | `orders` 생성 (entity=`CN`, 정산통화=`CNY`, deal_type=`OVERSEAS_DIRECT`) |
| 2 | 입금 등록 (CNY 39,733 / USD 인보이스 5,918.88) | `receipts` + `receipt_splits`(SALES 100%) |
| 3 | 05-05 상품대금 CNY 8,384 | `expenses` + `expense_allocations` → 주문 귀속 |
| 4 | 05-05 상품대금 CNY 3,726 | 〃 |
| 5 | 05-11 상품대금 CNY 2,066.90 | 〃 |
| 6 | 05-14 상품대금 CNY 11,540 | 〃 |
| 7 | 05-29 상품대금 CNY 36,007.90 + 인건비 CNY 1,809 | 〃 |
| 8 | 정산완료 처리 | `status=SETTLED`, 마진 스냅샷 저장, 주문 잠금 |

**결과**

```
총입금  CNY 39,733.00
총비용  CNY 63,533.80   (상품 61,724.80 + 인건비 1,809.00)
최종마진 CNY −23,800.80   ← 진짜 적자입니다
```

> ⚠️ **중요**: 이 거래처는 실제로 적자로 보입니다. 엑셀에서는 −100%짜리 행 네 개와 +5%짜리 행 하나로 흩어져 있어 알 수 없었습니다.
> 다만 **입금이 다른 시트(일반통장·법인통장)나 다른 기간에 있을 수도 있습니다.** 시스템에서는 이런 주문에 `⚠️ 입금 대비 지출 과다` 배지를 띄워 확인을 요청합니다.

## 시나리오 B. 일반통장 — 예치금 계좌

**실제 데이터**: 에이스 (일반통장 시트 57건), 메모 `收50万 结2107.5` (50만 받고 2,107.5 정산)

### B-1. 예치금 적립

| 업무 | 시스템 처리 |
|------|------------|
| 고객이 여러 번 입금, `☑ 예치금으로 적립` | `receipts` (order_id=NULL) <br> `receipt_splits` = `DEPOSIT_GENERAL` <br> `deposit_ledger` `IN_RECEIPT` (+) |

### B-2. 예치금 사용 (주문 발생)

**실제 데이터**: 일반통장 3행 — 더모음 파티

| 엑셀 | 값 |
|------|---:|
| KRW 입금액 | 3,492,829.32 |
| 수식 | `=C3/218.22` ← 환율이 수식 안에 |
| CNY 환산 | 16,006.00 |
| CNY 지출 | 14,750.00 |
| 마진 | 1,256.00 |
| 엑셀 % | 8.52% (= 1,256 ÷ 14,750) |

| 단계 | 시스템 처리 |
|------|------------|
| 1 | 새 거래 등록 → 더모음파티 / 일반통장, **적용환율 218.22 입력** |
| 2 | `receipts` (KRW 3,492,829.32, fx_rate=218.22, amount_cny=16,006.00) |
| 3 | `expenses`(GOODS, CNY 14,750) + 배분 |
| 4 | 자동 계산 |

**결과**

```
총입금   CNY 16,006.00
총비용   CNY 14,750.00
최종마진 CNY  1,256.00
마진율      7.85%   (= 1,256 ÷ 16,006)   ← 시스템 기본
원가대비    8.52%   (= 1,256 ÷ 14,750)   ← 엑셀 % 열과 동일
```

### B-3. 예치금 반환

| 업무 | 시스템 처리 |
|------|------------|
| 남은 예치금 일부 반환 | `deposit_ledger` `REFUND` (−), **사유 입력 필수** <br> 비용이 아니므로 `expenses` 생성 안 함 <br> 계좌 출금은 별도 출금 전표 |

## 시나리오 C. 법인통장 — 세금계산서 발행

**실제 데이터**: 아르미르샵49 (법인통장 시트 6행)

| 엑셀 열 | 값 | 수식 |
|---------|---:|------|
| C 입금액 | 3,142,691.27 | |
| D CNY 환산 | 14,416.93 | `=C6/218` |
| E CNY 지출 | 13,109.65 | |
| I 마진 | 1,307.28 | `=D6-E6-F6-G6-H6` |
| J % | 9.97% | `=I6/E6` |
| **M** | **3,456,960.397** | 수동 입력 |
| **N** | 3,142,691.27 | `=M6/1.1` |

### 시스템 처리

| 단계 | 처리 |
|------|------|
| 1 | 새 거래 등록 → 아르미르샵 / 법인통장 / `CORP_FULL` <br> **기존관리번호 = `아르미르샵49`** 로 보존 ⭐ |
| 2 | `receipts` (KRW 3,142,691.27, **fx_rate=218.00**, amount_cny=14,416.93) |
| 3 | `expenses`(GOODS, CNY 13,109.65) + 배분 |
| 4 | 세금계산서 생성 — `invoice_base=TOTAL_RECEIPT`, `vat_mode=EXCLUDED` |

**세금계산서 자동 산출**

```
발행대상금액 = 총입금 3,142,691원
공급가액     = 3,142,691원         (EXCLUDED → 대상금액 그대로)
부가세       =   314,269원         (× 10%)
합계금액     = 3,456,960원         ← 엑셀 M열 3,456,960.397 과 일치 ✓
```

**결과**

```
총입금   CNY 14,416.93
총비용   CNY 13,109.65
최종마진 CNY  1,307.28
마진율      9.07%   (시스템 기본)
원가대비    9.97%   (엑셀 % 열)
세금계산서  공급가액 3,142,691 + 부가세 314,269 = 3,456,960
```

### C-2. 세금계산서를 발행하지 않는 법인통장 거래 ⭐

법인통장 입금 483건 중 **369건(76.4%)은 M열이 비어 있습니다** = 발행하지 않았습니다.

| 업무 | 시스템 처리 |
|------|------------|
| 새 거래 등록 시 `☐ 세금계산서 발행 대상` 체크 해제 | `deal_type = CORP_NOBILL` <br> `orders.invoice_status = 'NONE'` <br> `accounting_class = 상품매출` (회계상으로는 여전히 매출) |

> 거래형태(세금계산서 발행 여부)와 회계분류(매출 성격)를 **따로 저장**하기 때문에, 발행 안 한 거래도 매출 통계에는 정상적으로 들어갑니다.

## 시나리오 D. 사이트 결제 (신규) ⭐


| 시스템 처리 |
|------------|

| `remittance_allocations` (order_id, alloc_krw=600,000) |
| `deposit_ledger` `USE_REMIT` **−600,000 (GOODS_FUND)** |

| 항목 | 금액 |
|------|-----:|
| 총 상품자금 | 1,000,000 |
| 송금완료 | 600,000 |
| **송금대기** | **400,000** |

```
매출인식액(NET) = 수수료 100,000
회사부담비용    = 포장비 15,000     ← 상품대금은 예치금에서 나가므로 회사 비용 아님
```

## 시나리오 F. 내부 자금이동 ⭐ (엑셀에서 분리된 부분)

**실제 데이터**: 해외송금 시트 52행 — `이우드림` USD 99,000 → CNY 672,190

### 엑셀에서의 문제

```
거래처 = 이우드림 (자기 회사)
USD 99,000 / CNY 672,190 / 지출 없음
→ 마진 수식이 지워져 있어 값은 없지만,
   CNY 672,190이 해외송금 "도착금액" 합계에 그대로 들어감
→ 16건 합계 CNY 7,516,792 = 전체 도착액의 33.7%가 매출로 부풀려짐
```

### 시스템 처리

| 단계 | 처리 |
|------|------|
| 1 | `내부 자금이동` 메뉴에서 등록 (주문 아님) |
| 2 | `internal_transfers` (from=`KR`, to=`CN`, USD 99,000 → CNY 672,190, fx 6.7898) |
| 3 | 한국 계좌 잔액 감소 / 중국 계좌 잔액 증가 |
| 4 | **매출·마진·거래처 순위 어디에도 들어가지 않음** |
| 5 | 대시보드에는 `🔁 내부 자금이동` 별도 줄로 표시 |

## 시나리오 G. 중국 운영비 월마감

**실제 데이터**: Sheet1

| 업무 | 시스템 처리 |
|------|------------|
| 급여 등록 (귀속월 필수) — 18명, 실지급 CNY 116,300 | `payrolls` → 확정 시 `expenses`(SALARY) 자동 생성 |
| 사회보험 4명분 CNY 4,664 | `payrolls.insurance_company` → `expenses`(INSURANCE) |

| 임시공 나머지 4주 CNY 59,503 — 창고 작업 | `expenses`(TEMP_LABOR) **미귀속** → 운영비 |
| 사무실 경비 CNY 33,055 | `expenses`(OFFICE) |

**월 마감 집계**

```
직원 급여        CNY 116,300   ← 실지급 기준 (엑셀은 기본급 111,450 사용)

사무실 경비      CNY  33,055
────────────────────────────
중국 운영비 합계  CNY 213,522

주문마진 합계    CNY   xxx,xxx
− 중국 운영비    CNY   213,522
────────────────────────────
= 최종 영업마진  CNY   xxx,xxx
```

> 엑셀의 `9月总合 218,707`과 다른 이유:
> ① 실지급(116,300) vs 기본급(111,450) → +4,850
> ② 임시공 중 주문 귀속분(10,035)이 운영비에서 빠짐 → −10,035

## 시나리오 H. 금액 수정 / 취소

### H-1. 금액 수정

```
상품비 CNY 15,000 → CNY 15,500 정정
1. 지출 상세 → 금액 수정
2. 사유 입력 필수: "공장 단가 정정"
3. 저장
   → change_logs: field=amount, old=15000.00, new=15500.00,
                  changed_by=박직원, changed_at=2026-05-12 14:22, reason=...
   → 주문 마진 자동 재계산
```

### H-2. 취소 (void)

```
잘못 입력된 송금 전표 취소
1. [취소] → 사유 입력 "계좌번호 오류"
2. remittances.is_void = TRUE   ← 행은 남습니다. 삭제 아님
3. deposit_ledger는 삭제하지 않고 반대부호 상쇄행 추가 (append-only 유지)
4. change_logs: action=VOID
```

### H-3. 정산완료 주문 수정

```
SETTLED 상태 → 전표 추가/수정/취소 차단
매니저 이상이 [잠금해제] + 사유 입력 시에만 가능
change_logs: action=UNLOCK → 대시보드 "이번 달 잠금해제 N건" 노출
```
