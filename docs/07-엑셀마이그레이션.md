### STEP 3 — 환율 수식 파싱 ⭐ (이 파일 전용 필수 단계)

일반통장 D열, 법인통장 D열의 수식에서 환율을 꺼냅니다.

```python
# D3 = "=C3/218.22"  →  fx_rate = 218.22, fx_rate_source = 'PARSED'
m = re.search(r'=\s*[A-Z]+\d+\s*/\s*([\d.]+)', formula)
```

| 시트 | 파싱 대상 | 추출되는 환율 |
|------|----------:|--------------|
| 일반통장 | 64건 | 48종 (201.93 ~ 231.57) |
| 법인통장 | 476건 | 132종 (201.17 ~ 231.57) |

> **공유수식 주의** — 연달아 같은 환율을 쓴 행은 엑셀이 수식을 한 번만 저장하고
> 나머지는 «D428과 같은 수식» 이라고만 적어 둡니다 (법인통장 61건, 일반통장 4건).
> 값만 읽으면 이 행들의 환율을 잃어버립니다. 구현에서는 원래 행의 수식을 찾아 풀어 읽습니다.
> 수식이 아예 없는 8건은 `입금액 ÷ CNY` 로 역산하고 화면에 「역산」 이라고 밝힙니다.

**⚠️ 헤더의 `환율적용 192` / `195`는 무시합니다.** 실제 수식 값과 30 가까이 차이 납니다.

파싱 실패 행은 `HOLD` 처리하고, `입금액 ÷ CNY환산액`으로 역산한 값을 제안합니다.

**⭐ 이우드림 16행 분리**

```
B열 = "이우드림"  →  internal_transfers 테이블로
  transfer_date = A열, usd_amount = C열, cny_arrival_amount = D열
  fx_rate_usd_cny = D ÷ C  (6.7481 ~ 6.8028)
```

**⭐ 거래처가 비어 있는 14행 — 중국 송금 ✅ 확정**

구현 후 실제 파일을 넣어 보니 **B열이 비었는데 C(USD)·D(CNY)만 있고 지출이 하나도 없는 행이 14건**
있었습니다. 합계 **CNY 5,654,262** (약 12억 원) 으로, 해외송금 도착금액의 25%입니다.

> **대표님 확인**: 「법인통장 · 일반통장 · 사이트통장에서 모여진 돈을 중국으로 송금한 내용」

즉 매출이 아니라 **회사 돈을 중국으로 보낸 것**입니다. `이우드림` 이라고 적힌 16건과 같은 내용인데
이름만 빠뜨린 것이라 함께 `internal_transfers` 로 넣습니다.

| 처리 | 내용 |
|------|------|
| 판정 기준 | 거래처 칸 비어 있음 + 지출 0건 + USD·CNY 둘 다 있음 |
| 넣는 곳 | `internal_transfers` — 주문·입금·매출 어디에도 만들지 않음 |
| 설정 | 가져오기 화면의 체크박스로 켜고 끕니다 (기본 켜짐). 끄면 넣지 않고 한 행씩 보여 드립니다 |
| 출금 계좌 | 엑셀에 없어 담당자가 고른 계좌 하나로 기록. 나중에 건별로 고칠 수 있습니다 |
| 원화 금액 | 엑셀에 없어 담당자가 넣은 USD→KRW 환율로 환산. 넣지 않으면 비워 둡니다 |

**⭐ 원화 환산은 이 14행에만 매깁니다**

`이우드림` 이라고 적힌 16건(USD 1,110,000)까지 원화로 빼면 한국 통장에서 나간 돈이
들어온 돈보다 커져 **잔액이 마이너스**가 됩니다. 대표님이 지목하신 것은 14행이므로
그 행들만 한국 계좌에서 출금 처리하고, `이우드림` 행은 출금 계좌와 원화 금액을 비워 둡니다.

```
한국 법인통장  입금 1,265,777,151  −  송금 1,159,807,366  =  105,969,785
한국 일반통장  입금   315,661,344                           315,661,344
```

가져오기가 끝나면 **이관 결과 통장 잔액**을 화면에 그대로 보여 드립니다.
실제 통장과 다르면 그 차액을 기초잔액으로 넣으시면 됩니다.

```
   deal_type              = CORP_FULL

   invoices.vat_amount    = M − C
   invoices.total_amount  = M
   invoices.vat_mode      = 'EXCLUDED'
   invoices.issue_status  = 'ISSUED'

M열이 비어 있으면 (369건):   ✅ 확정 — 이쪽도 부가세를 받으심

   accounting_class       = '상품매출'         ← 회계상으로는 여전히 매출
   → v_vat_unbilled 뷰에 자동으로 잡힘 (미발행 + 부가세 수취 목록)
```

D2 칸에 직원 이름 없이 금액만 있습니다. 막아 버리면 사회보험 합계가 엑셀(4,664)과 어긋나므로
**금액은 그대로 넣고** 「직원 미지정」 이라고 남깁니다. 누구 것인지 확인되면 고치시면 됩니다.

**⭐ 임시공 기간은 이어지는 주로 읽습니다**

`12/28-1/3`, `1/4-1/10`, `1/11-1/17` … 은 연달아 이어지는 주입니다.
기준연도를 행마다 그대로 쓰면 `12/28` 은 2026년 1월로 넘어가고 그 다음 `1/4` 는
2025년 1월로 돌아가 **한 해가 벌어집니다.** 앞 기간보다 뒤에 오도록 필요한 만큼 해를 넘깁니다.

```
기준연도 2025  →  12/28-1/3   2025-12-28 ~ 2026-01-03
                 1/04-1/10   2026-01-04 ~ 2026-01-10   ← 해를 넘김
                 1/11-1/17   2026-01-11 ~ 2026-01-17
                 1/18-1/24   2026-01-18 ~ 2026-01-24
                 1/24-1/31   2026-01-24 ~ 2026-01-31
```

**⚠️ 기간 혼재 — 섞지 않습니다 (대표님 지시)**

Sheet1은 제목이 `9月总合` 인데 임시공 기간은 12/28~1/31, 사무실 경비 날짜는 1~2월,
거기에 8~9월 항목까지 섞여 있습니다. 한 달로 뭉뚱그리지 않고 **각자 제 달로 보냅니다** —
그래야 월별 대시보드의 운영비가 맞습니다.

| 항목 | 귀속월 기준 |
|------|------------|
| 급여 · 사회보험 | 담당자가 고른 **귀속월** |
| 임시공 | 기간의 **끝 날짜** |
| 사무실 경비 | J열 **날짜**, 없으면 담당자가 정한 지출일 |

어느 달에 얼마가 들어가는지 **넣기 전에 표로 보여 드립니다**.

## 3-7. 예치금 기초잔액 ✅ 확정 — 0에서 시작

대표님 확인 결과 **넘어올 예치금 잔액이 없습니다.** 이관 규칙이 단순해집니다.

| 항목 | 처리 |
|------|------|
| 예치금 기초 `ADJUST` 행 | **생성하지 않음** |
| 모든 거래처 예치금 시작값 | **0** |
| 예치금 원장 테이블 | **유지** — 사이트 결제 루트가 반드시 필요로 함 |
| 일반통장 "입금만 있는 행" | 예치금 적립이 아니라 **주문 입금**으로 처리 |

> 예치금 개념 자체는 없어지지 않습니다. 사이트 결제는 구조상 고객 돈을 보관하므로
> 앞으로 발생하는 예치금은 원장에 정상적으로 쌓입니다. **과거 이월분만 0**입니다.

### ⭐ 대신 필요해진 것 — 에이스 미수금 처리

예치금이 0이면 일반통장 에이스의 **CNY 368,821.90 미회수 지출**은 갈 곳이 없습니다.
이 금액은 **미수금(받을 돈)** 으로 처리합니다.

| 이관 방법 | 처리 |
|----------|------|
| 1안 (권장) | 입금 없는 지출 44건을 `ORDER-MIG-에이스-미수` 주문 하나에 묶고, 입금 0 / 지출 CNY 368,822 상태로 `OPEN` 유지 → `v_receivables`가 자동으로 미수금으로 집계 |
| 2안 | 44건을 날짜 근접도로 여러 주문에 나눠 배분 (담당자 수작업 필요) |

**1안 결과**

```
ORDER-MIG-에이스-미수   거래처: 에이스 / 루트: 일반통장 / 상태: 진행중
├ 입금   없음
└ 지출   44건 합계 CNY 368,821.90
─────────────────────────────────────
미수금   CNY 368,821.90   (환율 220 기준 약 81,140,000원)
청구예정  CNY 401,600      (실측 마크업 8.89% 적용)
```

거래처 화면과 자금현황에 `⚠️ 받을 돈`으로 표시되며, 이후 입금이 들어오면 이 주문에 연결해 소진시킵니다.
