## 2. 가져오기 6단계

```
STEP 1  업로드        .xlsx → import_batches 생성
STEP 2  시트 감지     6개 시트 인식 → 처리 대상 선택
STEP 3  ⭐ 수식 파싱   D열 수식 `=C3/218.22` 에서 환율 218.22 추출
STEP 4  컬럼 매핑     자동 추천 + 수동 수정
STEP 5  검증 미리보기  ✅정상 / ⚠️경고 / ❌오류 / ⏸보류
STEP 6  실행          트랜잭션 일괄 생성 / [배치 되돌리기]
```

### STEP 3 — 환율 수식 파싱 ⭐ (이 파일 전용 필수 단계)

일반통장 D열, 법인통장 D열의 수식에서 환율을 꺼냅니다.

```python
# D3 = "=C3/218.22"  →  fx_rate = 218.22, fx_rate_source = 'PARSED'
m = re.search(r'=\s*[A-Z]+\d+\s*/\s*([\d.]+)', formula)
```

| 시트 | 파싱 대상 | 추출되는 환율 |
|------|----------:|--------------|
| 일반통장 | 64건 | 48종 (201.93 ~ 231.57) |
| 법인통장 | 476건 | 132종 (201.17 ~ 231.57) |

**⚠️ 헤더의 `환율적용 192` / `195`는 무시합니다.** 실제 수식 값과 30 가까이 차이 납니다.

파싱 실패 행은 `HOLD` 처리하고, `입금액 ÷ CNY환산액`으로 역산한 값을 제안합니다.

## 3-7. 예치금 기초잔액 ✅ 확정 — 0에서 시작

대표님 확인 결과 **넘어올 예치금 잔액이 없습니다.** 이관 규칙이 단순해집니다.

| 항목 | 처리 |
|------|------|
| 예치금 기초 `ADJUST` 행 | **생성하지 않음** |
| 모든 거래처 예치금 시작값 | **0** |
| 예치금 원장 테이블 | **유지** — 사이트 결제 루트가 반드시 필요로 함 |
| 일반통장 "입금만 있는 행" | 예치금 적립이 아니라 **주문 입금**으로 처리 |

> 예치금 개념 자체는 없어지지 않습니다. 사이트 결제는 구조상 고객 돈을 보관하므로
> 앞으로 발생하는 예치금은 원장에 정상적으로 쌓입니다. **과거 이월분만 0**입니다.

### ⭐ 대신 필요해진 것 — 에이스 미수금 처리

예치금이 0이면 일반통장 에이스의 **CNY 368,821.90 미회수 지출**은 갈 곳이 없습니다.
이 금액은 **미수금(받을 돈)** 으로 처리합니다.

| 이관 방법 | 처리 |
|----------|------|
| 1안 (권장) | 입금 없는 지출 44건을 `ORDER-MIG-에이스-미수` 주문 하나에 묶고, 입금 0 / 지출 CNY 368,822 상태로 `OPEN` 유지 → `v_receivables`가 자동으로 미수금으로 집계 |
| 2안 | 44건을 날짜 근접도로 여러 주문에 나눠 배분 (담당자 수작업 필요) |

**1안 결과**

```

```

거래처 화면과 자금현황에 `⚠️ 받을 돈`으로 표시되며, 이후 입금이 들어오면 이 주문에 연결해 소진시킵니다.
