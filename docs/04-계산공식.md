# 04. 계산 공식

> 화면·리포트·엑셀 내보내기가 모두 이 문서의 식만 사용합니다.
> **엑셀과 다른 부분은 ⚠️로 표시**했습니다.

---

## 0. 통화 환산 규칙

| 규칙 | 내용 |
|------|------|
| R-1 | 모든 전표는 `원통화 금액` + `건별 적용환율` + `환산 KRW` + `환산 CNY`를 저장 시점에 함께 확정 |
| R-2 | 환율이 나중에 바뀌어도 **과거 전표의 환산액은 재계산하지 않음** |
| R-3 | 환율 표기는 `KRW per 1 CNY` (예: 218.22 = 1위안당 218.22원) |
| R-4 | 반올림: KRW는 `settings.krw_rounding`(기본 FLOOR, 원 단위), CNY는 소수 둘째 자리 |
| R-5 | ⚠️ **환율은 반드시 데이터로 저장**. 엑셀처럼 수식에 넣지 않음 |

```
환산 CNY = 원통화가 KRW일 때  →  amount ÷ fx_rate
환산 KRW = 원통화가 CNY일 때  →  amount × fx_rate
```

> **엑셀 실태**: 헤더에는 `환율적용 192` / `195`라고 적혀 있으나 실제 수식은 `=C3/218.22`, `=C5/215.74` 등으로 일반통장 48종, 법인통장 132종의 값이 쓰이고 있었습니다(201.17 ~ 231.57). 헤더 숫자는 실제와 30 가까이 차이 납니다.

> **해외송금 주의**: USD 인보이스 금액은 통관 서류용 명목값입니다. 마진은 **CNY 실제 도착금액** 기준으로만 계산합니다.

## 1. 주문(ORDER) 단위 계산 ⭐

기준통화 `C` = `orders.settlement_currency` (해외송금=CNY, 그 외=KRW)

### 1-1. 입금 집계

```
총입금(GROSS_IN)   = Σ receipts.amount_[C]        ← 실제 통장에 들어온 금액 (부가세 포함)

  ├ 일반매출(SALES_IN) = Σ splits where kind='SALES'          ← 공급가액 · 회사 돈
  ├ 수수료수입(FEE_IN) = Σ splits where kind='FEE'            ← 공급가액 · 회사 돈
  ├ 부가세(VAT_IN)     = Σ splits where kind='VAT'            ← 국세청 돈
  └ 예치금(DEP_IN)     = Σ splits where kind LIKE 'DEPOSIT%'  ← 고객 돈

매출인식액 = SALES_IN + FEE_IN        ← 마진 계산의 분자는 항상 이것
```

> **엑셀과의 관계**: 법인통장 C열이 `SALES`, M−C가 `VAT`, M이 `receipts.amount`입니다.
> 엑셀은 C(공급가액)로 마진을 계산했는데 **이것은 회계적으로 옳습니다.** 부가세는 낼 돈이라 마진에 넣으면 안 됩니다.
> 다만 통장 잔액은 M 기준이어야 하므로, 시스템은 둘을 나눠 저장합니다.

### 1-2. 비용 집계 (`expense_allocations`로 이 주문에 배분된 금액만)

```
상품비(COST_GOODS)      = Σ alloc_[C]  where category = GOODS
대행통관비(COST_CUSTOMS) = Σ alloc_[C]  where category = CUSTOMS
인건비(COST_LABOR)      = Σ alloc_[C]  where category IN (LABOR_CN, TEMP_LABOR)
검품비(COST_INSPECT)    = Σ alloc_[C]  where category = INSPECT
포장비(COST_PACKING)    = Σ alloc_[C]  where category = PACKING
운송비(COST_SHIPPING)   = Σ alloc_[C]  where category = SHIPPING
기타비(COST_ETC)        = Σ alloc_[C]  where category IN (ETC_ORDER, BANK_FEE)

총비용(TOTAL_COST) = 위 7개 항목의 합
```

### 1-3. 마진 — 거래유형의 `revenue_basis`에 따라 달라집니다

#### ① `GROSS` — 해외송금 / 일반통장 / 법인통장

```
매출인식액 = SALES_IN            ← 공급가액. 부가세(VAT_IN)는 제외
최종마진   = 매출인식액 − 총비용
```

**법인통장 실제 예시 (6행 · 아르미르샵49)**

| 항목 | 금액 | 성격 |
|------|-----:|------|
| 실제 입금 (엑셀 M열) | 3,456,960 | 통장 잔액에 반영 |
| ├ 공급가액 `SALES` (엑셀 C열) | 3,142,691 | **매출인식액** |
| └ 부가세 `VAT` | 314,269 | 국세청 돈 |
| CNY 환산 (공급가액 ÷ 218.00) | CNY 14,416.93 | |
| 총비용 | CNY 13,109.65 | |
| **최종마진** | **CNY 1,307.28** | 마진율 9.07% |

> 엑셀 수식 `=D−E−F−G−H` (법인·일반통장 505건), `=D−E−F−G` (해외송금 415건)와 동일합니다.
> 다른 점은 **여러 날짜에 흩어진 지출이 모두 하나의 주문에 합산**된다는 것입니다.

#### ② `NET` — 사이트 결제 ⭐ (부가세 포함 확정 반영)

상품예치금과 부가세는 **둘 다 회사 돈이 아닙니다.**

```
수수료수입(총액)   = FEE_IN                              ← 부가세 포함
수수료 공급가액    = FEE_IN ÷ 1.1                         ← 실제 회사 수익
수수료 부가세      = FEE_IN − 공급가액                     ← 국세청에 낼 돈(예수금)

매출인식액   = 수수료 공급가액                            (settings.margin_vat_basis = SUPPLY)
회사부담비용 = 총비용 − 예치금으로 지출한 상품대금
최종마진     = 매출인식액 − 회사부담비용
```

| 항목 | 금액(KRW) | 성격 |
|------|----------:|------|
| 총 입금액 | 1,100,000 | |
| ├ 상품구매 예치금 | 1,000,000 | **고객 돈(부채)** |
| └ 구매대행 수수료 | 100,000 | 부가세 포함 |
| 　├ 공급가액 | 90,909 | **회사 수익** |
| 　└ 부가세 | 9,091 | **국세청 돈(예수금)** |
| 회사부담비용 (포장/기타) | −15,000 | |
| **최종마진** | **75,909** | |
| 마진율 | 83.5% | (공급가액 기준) |

> **왜 공급가액 기준인가**: 부가세 9,091원은 잠시 보관했다가 납부할 돈입니다.
> 고객 예치금과 성질이 같습니다. 총액 100,000으로 마진을 잡으면 9,091원을 이익으로 착각합니다.
> `settings.margin_vat_basis = GROSS` 로 바꾸면 총액 기준(마진 85,000)으로 볼 수 있습니다.

## 2. 마진율 — ⚠️ 엑셀과 분모가 다릅니다

### 2-1. 문제

엑셀은 세 시트 **전부, 1,047개 셀**에서 이렇게 계산합니다.

```
해외송금  I4 = H4/E4      ← 마진 ÷ CNY 지출금액
일반통장  J3 = I3/E3      ← 마진 ÷ CNY 지출금액
법인통장  J3 = I3/E3      ← 마진 ÷ CNY 지출금액
```

이것은 매출 대비 마진율이 아니라 **원가 대비 수익률(markup)** 입니다.

### 2-2. 시스템의 계산

두 지표를 **나란히** 보여드립니다. 어느 쪽도 숨기지 않습니다.

```
마진율(기본)        = 최종마진 ÷ 매출인식액 × 100     ← 회계상 표준
원가대비 수익률(보조) = 최종마진 ÷ 총비용     × 100     ← 엑셀의 % 열과 같은 값
```

**실제 데이터 대조 (해외송금 6행, 케이에스 글로벌)**

| 지표 | 계산 | 값 |
|------|------|---:|
| 엑셀 `%` 열 = 원가대비 수익률 | 13,248.49 ÷ 102,416.51 | 12.94% |
| 시스템 기본 = 마진율 | 13,248.49 ÷ 115,665 | **11.45%** |

**4개월 전체 (내부 자금이동 제외 전 기준)**

| 시트 | 총입금 | 마진 | 마진율 | 원가대비 |
|------|-------:|-----:|------:|--------:|
| 해외송금 | CNY 22,272,750 | CNY 4,034,613 | 18.11% | 44.58% |
| 법인통장 | CNY 5,287,164 | CNY 347,476 | **6.57%** | 7.02% |
| 일반통장 | CNY 1,448,423 | CNY −265,379 | −18.32% | −15.50% |

> 일반통장이 음수인 것은 계산 오류가 아니라 **예치금 구조** 때문입니다. 이전에 받아둔 예치금으로 지출하고 있어 이 기간 입금보다 지출이 많습니다. 예치금 기초잔액을 입력하면 정상 범위로 잡힙니다.

**분모가 0일 때**: 매출인식액 = 0 이면 마진율은 `—`로 표시합니다. 엑셀처럼 `#DIV/0!`(49건) 이 뜨지 않습니다.

## 3. 주문 송금 진행상태 (계산값)

```
송금완료액 = Σ remittance_allocations.alloc_krw  where status IN ('SENT','ARRIVED')
송금대기금 = 상품예치금(DEP_IN) − 송금완료액

송금완료액 = 0                 → 송금대기 (PENDING)
0 < 송금완료액 < 상품예치금     → 일부송금 (PARTIAL)
송금완료액 ≥ 상품예치금         → 송금완료 (DONE)
```

## 4. 거래처 단위 계산

기준통화 = KRW

| 항목 | 공식 |
|------|------|
| 누적 입금액 | `Σ receipts.amount_krw` (is_void=false) |
| 누적 상품구매액 | `Σ alloc_krw` where category = GOODS |
| 누적 인건비 | `Σ alloc_krw` where category IN (LABOR_CN, TEMP_LABOR) |
| 누적 통관비 | `Σ alloc_krw` where category = CUSTOMS |
| 누적 수수료 | `Σ receipt_splits.amount_krw` where split_kind = FEE |
| 누적 마진 | `Σ 주문별 최종마진(KRW)` |
| **현재 예치금** | `Σ deposit_ledger.amount_krw` |
| **중국 송금대기금** | `Σ deposit_ledger.amount_krw` where deposit_kind = GOODS_FUND |
| 미정산금 | 진행중(OPEN) 주문의 `총입금 − 총비용` 합계 |
| 세금계산서 발행금액 | `Σ invoices.total_amount` where issue_status = ISSUED |
| 세금계산서 발행예정 | `Σ invoices.total_amount` where issue_status = PENDING |

> ⚠️ **`partners.is_internal = TRUE`인 거래처(이우드림 등)는 모든 매출·마진 집계에서 제외**합니다.

## 4-2. 미수금 (받을 돈) ⭐ 신규

> 엑셀 일반통장의 에이스 건(CNY 368,822 미회수)에서 필요성이 확인된 지표입니다.

```
주문별 미수금 = 총비용 − 총입금        (양수일 때만, 진행중 주문 한정)
거래처 미수금 = Σ 주문별 미수금

청구예정액   = 주문별 미수금 × (1 + 거래처 기본 마크업율)
             ※ 에이스의 경우 실측 마크업 8.89% → 청구예정 CNY 401,600
```

**화면 처리**

| 상황 | 표시 |
|------|------|
| 미수금 발생 | 주문 목록·거래처 화면에 `⚠️ 받을 돈` 배지 |
| 미수금이 30일 이상 | 주황 경고 |
| 미수금이 90일 이상 | 빨강 경고 + 대시보드 알림 |

**주의**: 지출이 먼저 나가고 입금이 나중에 오는 것이 정상 흐름일 수 있으므로,
미수금 자체를 오류로 처리하지 않습니다. **나이(경과일)로 관리**합니다.

## 5. 자금현황 ⭐

```
① 전체 계좌잔액
   = Σ accounts.opening_balance
   + Σ receipts.amount              (입금)
   − Σ expenses.amount              (지출, payment_status = 'PAID')
   − Σ remittances.krw_amount       (고객자금 송금)
   − Σ remittances.bank_fee_krw
   − Σ internal_transfers.krw_amount (내부 자금이동 출금 · KR 계좌)
   + Σ internal_transfers.cny_arrival_amount (내부 자금이동 입금 · CN 계좌)
   ※ 계좌 통화별 계산 후 KRW 환산 합계, entity 별 소계 병행 표시

② 고객 예치금 (부채)   = Σ deposit_ledger.amount_krw
③ 중국 송금대기금      = Σ deposit_ledger.amount_krw where deposit_kind = 'GOODS_FUND'
                          ※ ③은 ②의 부분집합 — 중복 차감 금지
④ 회사 수수료(미정산)  = Σ receipt_splits.amount_krw where split_kind='FEE'
                          and 소속 주문 status = 'OPEN'
⑤ 미지급 비용        = Σ expenses.amount_krw where payment_status = 'PLANNED'
⑥ 부가세 예수금 ⭐    = Σ receipt_splits.amount_krw where split_kind = 'VAT'
                         ※ 실제로 받아서 갖고 있는 부가세. 국세청에 낼 돈 — 회사 돈이 아님
                         ※ 세금계산서가 아니라 '받은 돈'에서 집계 (미발행분도 빠짐없이)

⑦ 실제 사용가능 자금  = ① − ② − ⑤ − ⑥

--- 별도 표시 (자산이지 잔액이 아님) ---
⑧ 미수금(받을 돈) ⭐  = Σ v_receivables.receivable
                         ※ 지출은 나갔는데 아직 못 받은 돈
```

| 항목 | 예시 | 성격 |
|------|-----:|------|
| ① 전체 계좌잔액 | 120,000,000 | |
| ② 고객 예치금 | 80,000,000 | 고객 돈 |
| ③ ㄴ 중 송금대기금 | 65,000,000 | 〃 |
| ⑤ 미지급 비용 | 0 | 줄 돈 |
| ⑥ 부가세 예수금 | 22,933,364 | 국세청 돈 |
| **⑦ 실제 사용가능 자금** | **17,066,636** | **회사 돈** |
| ⑧ 미수금 (받을 돈) | 81,140,000 | 받을 자산 |

> **⑧ 미수금을 왜 따로 두는가**: 엑셀 분석에서 에이스 한 곳에 CNY 368,822(약 8,100만원)의
> 미회수 지출이 발견됐습니다. 통장에 없는 돈이므로 잔액에 더하지 않지만,
> **받을 권리가 있는 자산**이므로 화면에 반드시 보여야 합니다.

## 6. 세금계산서 계산 (거래유형 설정 기반)

### 6-1. 발행 대상 판단 — ⚠️ 루트로 자동 판단 금지

> 법인통장 입금 483건 중 세금계산서를 발행한 건은 **114건(23.6%)** 뿐이었습니다.
> 따라서 "법인통장 = 발행" 같은 자동 판단을 하지 않고, **주문마다 발행여부 플래그**를 둡니다.

```
발행 대상 = orders.invoice_status ≠ 'NONE'
기본값    = deal_types.invoice_default  (담당자가 건별로 변경 가능)
```

### 6-2. 발행대상금액 (`target_amount`)

| `invoice_base` | target_amount |
|----------------|---------------|
| `NONE` | 0 |
| `TOTAL_RECEIPT` | 주문 총입금액 (KRW) |
| `FEE_ONLY` | 수수료수입 합계 |
| `CUSTOMS_ONLY` | 대행통관비 합계 |
| `MARGIN` | 주문 최종마진 |
| `MANUAL` | 담당자 직접 입력 |

자동 산출값을 수정하면 `target_amount_source = 'MANUAL'`로 바뀌고 **사유 입력이 필수**이며 변경이력에 남습니다.

### 6-3. 공급가액 / 부가세 / 합계

```
[EXCLUDED] 부가세 별도      ← 법인통장 확정값 ⭐
   공급가액 = target_amount
   부가세   = ROUND_RULE(target_amount × vat_rate)
   합계     = 공급가액 + 부가세

[INCLUDED] 부가세 포함
   공급가액 = ROUND_RULE(target_amount ÷ (1 + vat_rate))
   부가세   = target_amount − 공급가액
   합계     = target_amount

[EXEMPT] 면세 / [ZERO] 영세율
   공급가액 = target_amount,  부가세 = 0,  합계 = target_amount
```

## 7. 대시보드 월별 지표

기간 = `[월초, 월말]`, 기준일 = 전표 발생일

| 지표 | 공식 |
|------|------|
| 총 거래액 | `Σ receipts.amount_krw` — ⚠️ `is_internal` 거래처 제외 |
| 해외송금 / 일반통장 / 법인통장 / 사이트 거래액 | ↑ 루트별 |
| 내부 자금이동 | `Σ internal_transfers` — **별도 표시, 거래액에 미포함** ⭐ |
| 총 상품구매액 | `Σ expenses.amount_krw` where category = GOODS |
| 대행통관 수익 | `Σ 주문마진` where deal_type.code = `CORP_CUSTOMS` |
| 구매대행 수수료 | `Σ receipt_splits.amount_krw` where split_kind = FEE |
| 인건비 수익 | `Σ (인건비 청구액 − 인건비 지출액)` ⚠️확인필요 |
| 기타 수익 | 위에 속하지 않는 주문마진 합계 |
| **중국 운영비** | `Σ expenses.amount_krw` where cost_type = OPERATING **and 주문 미귀속** |
| ├ 직원 급여 | ↑ where category IN (SALARY, INSURANCE) — **실지급액 기준** ⭐ |
| ├ 임시공 비용 | ↑ where category = TEMP_LABOR and 주문 미귀속 |
| └ 사무실 경비 | ↑ where category = OFFICE |
| **최종 영업마진** | `Σ 주문별 최종마진 − 중국 운영비` |
| 마진율 | `최종 영업마진 ÷ 총 매출인식액 × 100` |
| 고객 예치금 / 송금대기금 | 월말 시점 `deposit_ledger` 합계 |
| 세금계산서 발행예정 / 완료 | `Σ invoices.total_amount` by issue_status |

**거래처별 순위**

```sql
SELECT p.name,
       SUM(매출인식액) AS revenue,
       SUM(최종마진)   AS margin,
       SUM(최종마진) / NULLIF(SUM(매출인식액),0) * 100 AS margin_rate
FROM orders o JOIN partners p ON p.id = o.partner_id
WHERE o.order_date BETWEEN :from AND :to
  AND o.is_void = FALSE
  AND p.is_internal = FALSE          -- 이우드림 자체 거래 제외
GROUP BY p.name
ORDER BY margin DESC LIMIT 10;
```

## 8. 계좌 잔액

```
계좌잔액(A, 기준일)
 = opening_balance
 + Σ receipts.amount            where account_id=A, receipt_date ≤ 기준일, not void
 − Σ expenses.amount            where account_id=A, paid_at ≤ 기준일, status='PAID', not void
 − Σ remittances.krw_amount     where from_account_id=A, remit_date ≤ 기준일, status≠'CANCELLED'
 − Σ remittances.bank_fee_krw   where from_account_id=A, ...
 + Σ remittances.cny_arrival_amount where to_account_id=A, status='ARRIVED'
 − Σ internal_transfers.krw_amount  where from_account_id=A
 + Σ internal_transfers.cny_arrival_amount where to_account_id=A
```
