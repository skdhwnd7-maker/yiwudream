# 02. 데이터베이스 설계

## 0. 설계 규칙

| 규칙 | 내용 |
|------|------|
| 금액 타입 | `NUMERIC(18,2)` — 부동소수점(float) 사용 금지 |
| 환율 타입 | `NUMERIC(18,6)` — 건별 저장, 고정환율 없음 |
| 삭제 | **물리 삭제 금지.** `is_void` 플래그 + 취소사유 기록 |
| 이력 | 모든 금액성 테이블은 `change_logs`에 필드 단위 변경이력 기록 |
| 시각 | 모든 테이블 `created_at / created_by / updated_at / updated_by` 필수 |
| 자금주체 | `entity` = `KR`(한국 이우드림무역) / `CN`(중국법인) — 절대 혼합 집계하지 않음 |
| 통화 | 원통화 금액 + 적용환율 + 환산액(KRW/CNY)을 **모두 저장** (사후 환율 변경에도 과거 값 불변) |

### 2-5. `deal_types` — 거래유형 ⭐ (세무 규칙 설정화)

> **요구사항: 세금계산서 대상금액 계산을 하드코딩하지 말 것.**
> 모든 세무 규칙은 이 테이블의 설정값으로만 동작합니다.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGSERIAL PK | |
| code | VARCHAR(30) UNIQUE | |
| name | VARCHAR(50) | 표시명 |
| revenue_basis | VARCHAR(10) | `GROSS`(총액매출) / `NET`(순액=수수료만) |
| invoice_base | VARCHAR(20) | 세금계산서 대상금액 산출 기준 (아래 표) |
| vat_mode | VARCHAR(10) | `INCLUDED`(부가세 포함) / `EXCLUDED`(별도) / `EXEMPT`(면세) / `ZERO`(영세율) |

| rounding | VARCHAR(10) | `ROUND`/`FLOOR`/`CEIL` (원 단위) |

| default_route | VARCHAR(20) | |
| is_active | BOOLEAN | |

**`invoice_base` 옵션**

| 값 | 세금계산서 대상금액 |
|----|-------------------|
| `NONE` | 발행 대상 아님 (0) |
| `TOTAL_RECEIPT` | 주문 총입금액 전체 |
| `FEE_ONLY` | 구매대행 수수료만 |
| `CUSTOMS_ONLY` | 대행통관비만 |
| `MARGIN` | 최종 마진 금액 |
| `MANUAL` | 담당자가 직접 입력 |

**초기 데이터(제안)**

| code | name | revenue_basis | invoice_base | vat_mode | accounting_class |
|------|------|---------------|--------------|----------|------------------|
| OVERSEAS_DIRECT | 해외송금 직접거래 | GROSS | NONE | EXEMPT | 해외매출 |
| GEN_DEPOSIT | 일반통장 예치정산 | GROSS | MANUAL | INCLUDED | 용역매출 |
| CORP_FULL | 법인통장 전액발행 | GROSS | TOTAL_RECEIPT | INCLUDED | 상품매출 |
| CORP_CUSTOMS | 대행통관 용역 | GROSS | CUSTOMS_ONLY | EXCLUDED | 용역매출 |
| SITE_AGENCY | 사이트 구매대행 | **NET** | **FEE_ONLY** | ⚠️확인필요 | 중개수수료 |

> ⚠️ `SITE_AGENCY`의 `vat_mode`(수수료 부가세 포함/별도)는 대표님 확인 후 설정합니다. 기본값은 비워두고 최초 설정 시 필수 입력으로 강제합니다.

### 3-3. `receipt_splits` — 입금 성격 분해 ⭐ (사이트 루트 필수)

> 1,100,000원 입금 = 상품예치금 1,000,000 + 수수료 100,000 을 표현하는 테이블

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGSERIAL PK | |
| receipt_id | BIGINT FK | |
| split_kind | VARCHAR(20) | `DEPOSIT_GOODS`(상품구매 예치금) / `FEE`(구매대행 수수료) / `SALES`(일반 매출) / `DEPOSIT_GENERAL`(용도미지정 예치) |
| amount | NUMERIC(18,2) | |
| amount_krw / amount_cny | NUMERIC(18,2) | |

**제약: `SUM(receipt_splits.amount) = receipts.amount`** (DB 트리거로 강제)

| 루트 | 기본 분해 |
|------|----------|
| SITE | `DEPOSIT_GOODS` + `FEE` (수수료율 또는 금액 직접입력) |
| BANK_GEN (주문 미지정) | `DEPOSIT_GENERAL` 100% |
| BANK_GEN (주문 지정) | `SALES` 100% |
| BANK_CORP | `SALES` 100% |
| OVERSEAS | `SALES` 100% |

### 3-4. `deposit_ledger` — 고객 예치금 원장 ⭐ (append-only)

> **회사 돈과 고객 돈을 분리하는 핵심 테이블.** 행은 추가만 되며 수정/삭제되지 않습니다.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGSERIAL PK | |
| partner_id | BIGINT FK | |
| deposit_kind | VARCHAR(20) | `GOODS_FUND`(상품구매자금 — 송금대기 대상) / `GENERAL`(용도미지정) |
| movement | VARCHAR(20) | `IN_RECEIPT`(+) / `USE_ORDER`(−) / `USE_REMIT`(−) / `REFUND`(−) / `ADJUST`(±) |
| amount_krw | NUMERIC(18,2) | 부호 포함 (증가 +, 감소 −) |
| movement_date | DATE | |
| ref_table / ref_id | VARCHAR/BIGINT | 근거 전표 (receipt / remittance / order) |
| order_id | BIGINT FK NULL | |
| reason | TEXT | `ADJUST`·`REFUND` 시 필수 |
| created_by / created_at | | |

**잔액 계산**
```sql
-- 거래처별 예치금 잔액
SELECT partner_id, deposit_kind, SUM(amount_krw) AS balance
FROM deposit_ledger GROUP BY partner_id, deposit_kind;

-- 중국 송금대기금 (회사 전체)
SELECT SUM(amount_krw) FROM deposit_ledger WHERE deposit_kind = 'GOODS_FUND';
```

| status | VARCHAR(20) | `DRAFT`(작성중)/`SENT`(송금완료)/`ARRIVED`(도착확인)/`CANCELLED` |
| memo | TEXT | |

### 4-2. `remittance_allocations` — 송금↔주문/거래처 배분 ⭐

> **여러 고객의 돈을 합쳐 한 번에 송금**하는 경우를 위한 N:M 연결

| partner_id | BIGINT FK | |

| alloc_cny | NUMERIC(18,2) | 이 거래처 몫 도착 CNY |

**제약: `SUM(alloc_krw) = remittances.krw_amount`**

> 송금 확정 시 배분된 각 거래처에 대해 `deposit_ledger`에 `USE_REMIT` (−) 행이 자동 생성되어 송금대기금이 줄어듭니다.

### 6-3. 임시공 / 사무실 경비

별도 테이블을 만들지 않고 **`expenses`를 그대로 사용**하되, 화면만 분리합니다.

| 화면 | 필터 | 추가 입력 필드 |
|------|------|--------------|
| 임시공 관리 | `category = TEMP_LABOR` | `work_period_from/to`, `work_desc`, **귀속 주문**(= expense_allocations) |
| 사무실 경비 | `category = OFFICE` | `payment_method`, `memo` |

→ 이를 위해 `expenses`에 선택 컬럼 추가: `work_period_from DATE`, `work_period_to DATE`, `work_desc VARCHAR(200)`

> **임시공 비용이 특정 고객 작업 때문에 발생한 경우** `expense_allocations`로 주문에 연결 → 그 주문의 실제 마진에서 자동 차감됩니다. 연결하지 않으면 운영비로 집계됩니다.

## 8. DDL 초안 (PostgreSQL, 핵심 테이블 발췌)

```sql
-- 주문 (정산번호)
CREATE TABLE orders (
  id                  BIGSERIAL PRIMARY KEY,
  order_no            VARCHAR(20)  NOT NULL UNIQUE,
  partner_id          BIGINT       NOT NULL REFERENCES partners(id),
  route               VARCHAR(20)  NOT NULL
                        CHECK (route IN ('OVERSEAS','BANK_GEN','BANK_CORP','SITE')),
  deal_type_id        BIGINT       NOT NULL REFERENCES deal_types(id),
  accounting_class    VARCHAR(30)  NOT NULL,
  entity              VARCHAR(2)   NOT NULL CHECK (entity IN ('KR','CN')),
  settlement_currency CHAR(3)      NOT NULL,
  title               VARCHAR(200),
  order_date          DATE         NOT NULL,
  status              VARCHAR(20)  NOT NULL DEFAULT 'OPEN'
                        CHECK (status IN ('OPEN','SETTLED','CANCELLED')),
  settled_at          TIMESTAMPTZ,
  settled_by          BIGINT REFERENCES users(id),
  invoice_status      VARCHAR(20)  NOT NULL DEFAULT 'NONE',
  usd_invoice_amount  NUMERIC(18,2),
  memo                TEXT,
  is_void             BOOLEAN      NOT NULL DEFAULT FALSE,
  void_reason         TEXT,
  voided_by           BIGINT REFERENCES users(id),
  voided_at           TIMESTAMPTZ,
  created_by          BIGINT NOT NULL REFERENCES users(id),
  created_at          TIMESTAMPTZ  NOT NULL DEFAULT now(),
  updated_by          BIGINT REFERENCES users(id),
  updated_at          TIMESTAMPTZ
);
CREATE INDEX idx_orders_partner_date ON orders(partner_id, order_date DESC);
CREATE INDEX idx_orders_route_status ON orders(route, status) WHERE is_void = FALSE;

-- 입금
CREATE TABLE receipts (
  id           BIGSERIAL PRIMARY KEY,
  receipt_no   VARCHAR(20) NOT NULL UNIQUE,
  order_id     BIGINT REFERENCES orders(id),
  partner_id   BIGINT NOT NULL REFERENCES partners(id),
  account_id   BIGINT NOT NULL REFERENCES accounts(id),
  route        VARCHAR(20) NOT NULL,
  entity       VARCHAR(2)  NOT NULL,
  receipt_date DATE        NOT NULL,
  source       VARCHAR(20) NOT NULL DEFAULT 'DIRECT'
                 CHECK (source IN ('DIRECT','FROM_DEPOSIT')),
  currency     CHAR(3)     NOT NULL,
  amount       NUMERIC(18,2) NOT NULL CHECK (amount > 0),
  fx_rate      NUMERIC(18,6),
  amount_krw   NUMERIC(18,2) NOT NULL,
  amount_cny   NUMERIC(18,2),
  usd_amount   NUMERIC(18,2),
  memo         TEXT,
  is_void      BOOLEAN NOT NULL DEFAULT FALSE,
  void_reason  TEXT, voided_by BIGINT, voided_at TIMESTAMPTZ,
  created_by   BIGINT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_by   BIGINT, updated_at TIMESTAMPTZ
);

-- 입금 성격 분해 (사이트: 예치금 + 수수료)
CREATE TABLE receipt_splits (
  id         BIGSERIAL PRIMARY KEY,
  receipt_id BIGINT NOT NULL REFERENCES receipts(id),
  split_kind VARCHAR(20) NOT NULL
               CHECK (split_kind IN ('DEPOSIT_GOODS','DEPOSIT_GENERAL','FEE','SALES')),
  amount     NUMERIC(18,2) NOT NULL CHECK (amount >= 0),
  amount_krw NUMERIC(18,2) NOT NULL,
  amount_cny NUMERIC(18,2)
);

-- 예치금 원장 (append-only)
CREATE TABLE deposit_ledger (
  id            BIGSERIAL PRIMARY KEY,
  partner_id    BIGINT NOT NULL REFERENCES partners(id),
  deposit_kind  VARCHAR(20) NOT NULL CHECK (deposit_kind IN ('GOODS_FUND','GENERAL')),
  movement      VARCHAR(20) NOT NULL
                  CHECK (movement IN ('IN_RECEIPT','USE_ORDER','USE_REMIT','REFUND','ADJUST')),
  amount_krw    NUMERIC(18,2) NOT NULL,   -- 증가 +, 감소 -
  movement_date DATE   NOT NULL,
  ref_table     VARCHAR(50),
  ref_id        BIGINT,
  order_id      BIGINT REFERENCES orders(id),
  reason        TEXT,
  created_by    BIGINT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_deposit_partner ON deposit_ledger(partner_id, deposit_kind);
-- append-only 강제
CREATE RULE deposit_ledger_no_update AS ON UPDATE TO deposit_ledger DO INSTEAD NOTHING;
CREATE RULE deposit_ledger_no_delete AS ON DELETE TO deposit_ledger DO INSTEAD NOTHING;

-- 지출
CREATE TABLE expenses (
  id             BIGSERIAL PRIMARY KEY,
  expense_no     VARCHAR(20) NOT NULL UNIQUE,
  entity         VARCHAR(2)  NOT NULL,
  expense_date   DATE        NOT NULL,
  category_id    BIGINT NOT NULL REFERENCES expense_categories(id),
  partner_id     BIGINT REFERENCES partners(id),
  vendor_name    VARCHAR(100),
  account_id     BIGINT REFERENCES accounts(id),
  payment_method VARCHAR(20),
  currency       CHAR(3) NOT NULL,
  amount         NUMERIC(18,2) NOT NULL CHECK (amount > 0),
  fx_rate        NUMERIC(18,6),
  amount_krw     NUMERIC(18,2) NOT NULL,
  amount_cny     NUMERIC(18,2),
  payment_status VARCHAR(20) NOT NULL DEFAULT 'PAID'
                   CHECK (payment_status IN ('PLANNED','PAID')),
  paid_at        DATE,
  work_period_from DATE, work_period_to DATE, work_desc VARCHAR(200),
  memo           TEXT,
  is_void        BOOLEAN NOT NULL DEFAULT FALSE,
  void_reason    TEXT, voided_by BIGINT, voided_at TIMESTAMPTZ,
  created_by     BIGINT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_by     BIGINT, updated_at TIMESTAMPTZ
);

-- 지출 → 주문 배분
CREATE TABLE expense_allocations (
  id          BIGSERIAL PRIMARY KEY,
  expense_id  BIGINT NOT NULL REFERENCES expenses(id),
  order_id    BIGINT NOT NULL REFERENCES orders(id),
  alloc_amount NUMERIC(18,2) NOT NULL CHECK (alloc_amount > 0),
  alloc_krw   NUMERIC(18,2) NOT NULL,
  alloc_cny   NUMERIC(18,2),
  alloc_basis VARCHAR(20) NOT NULL DEFAULT 'AMOUNT',
  memo        TEXT,
  UNIQUE (expense_id, order_id)
);

-- 변경이력
CREATE TABLE change_logs (
  id         BIGSERIAL PRIMARY KEY,
  table_name VARCHAR(50) NOT NULL,
  record_id  BIGINT      NOT NULL,
  action     VARCHAR(20) NOT NULL,
  field_name VARCHAR(50),
  old_value  TEXT,
  new_value  TEXT,
  changed_by BIGINT NOT NULL REFERENCES users(id),
  changed_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  reason     TEXT,
  ip_address INET,
  request_id UUID
);
CREATE INDEX idx_changelog_record ON change_logs(table_name, record_id, changed_at DESC);
```

## 9. 무결성 제약 요약

| # | 제약 | 구현 |
|---|------|------|
| 1 | `SUM(receipt_splits) = receipts.amount` | DB 트리거 |
| 2 | `SUM(expense_allocations) ≤ expenses.amount` | DB 트리거 |
| 3 | `SUM(remittance_allocations) = remittances.krw_amount` | DB 트리거 |
| 4 | 예치금 잔액 < 0 차단 | 트랜잭션 내 검증 (초과 사용 시 경고 후 승인자만 허용) |

| 7 | 금액 필드 변경 시 사유 필수 | 애플리케이션 |
