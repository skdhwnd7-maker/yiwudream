# 09. 기술스택 · 개발 계획

---

## 1. 기술스택 제안

| 영역 | 제안 | 이유 |
|------|------|------|
| 프레임워크 | **Next.js 15 (App Router) + TypeScript** | 한 프로젝트로 화면·API 동시 개발, 사내 배포 단순 |
| DB | **PostgreSQL 16** | `NUMERIC` 정확한 금액 계산, 트랜잭션·제약조건 강력 |
| ORM | **Prisma** | 타입 안전, 마이그레이션 관리, 감사 미들웨어 구현 용이 |
| UI | **Tailwind CSS + shadcn/ui** | 밀집형 표 화면에 적합 |
| 표/그리드 | **TanStack Table** | 정렬·필터·고정열·합계행 |
| 차트 | **Recharts** | 대시보드 추이·구성 |
| 엑셀 | **SheetJS(xlsx) + exceljs** | 가져오기/내보내기. **수식 문자열 읽기 필요** ⭐ |
| 인증 | **Auth.js (Credentials)** + bcrypt | 사내 계정, 외부 의존 없음 |
| 배포 | **Docker Compose** (app + postgres + nginx) | 사내 서버 1대로 운영 가능 |

> **엑셀 라이브러리 주의**: 이 파일은 환율이 수식(`=C3/218.22`)에만 있으므로, **수식 문자열을 읽을 수 있는 라이브러리**가 필수입니다. 값만 읽는 라이브러리를 쓰면 환율 정보를 못 가져옵니다.

**대안 (더 단순하게)**
- DB를 SQLite로 (직원 5명 이하, 단일 서버) → 백업이 파일 복사로 끝남
- 다만 동시 입력·대용량 집계는 PostgreSQL이 유리하므로 권장은 PostgreSQL

## 2. 금액 처리 규칙 (구현 필수)

```ts
// ❌ 금지
const margin = 3492829.32 / 218.22        // float 오차

// ✅ 필수
import { Decimal } from 'decimal.js'
const cny = new Decimal(krw).div(fxRate).toDecimalPlaces(2)
```

| 규칙 | 내용 |
|------|------|
| DB | `NUMERIC(18,2)` — `FLOAT`/`REAL` 금지 |
| 서버 | `Decimal.js` 또는 `Prisma.Decimal` |
| 클라이언트 | 문자열로 전달, 표시 직전에만 포맷 |
| 반올림 | 중간 계산에서 하지 않고 **최종 표시·저장 시 1회만** |

## 3. 개발 단계

### Phase 0 — 설계 확정 ← **지금 여기**

- [x] 엑셀 원본 전 시트·전 수식 분석
- [x] 데이터베이스 구조 / 계산공식 / 화면 / 거래흐름 / 마이그레이션 설계
- [ ] **대표님 검토 및 확인 항목 회신** (아래 4장)

### Phase 1 — 기반 (1~2주)
- 프로젝트 셋업, DB 스키마 생성
- 로그인·권한
- 설정: 계좌 / 비용분류 / **거래유형** / 사용자
- 거래처 관리 + **별칭 병합 기능**
- **감사 미들웨어 (change_logs)** — 이후 모든 기능이 이 위에 얹힘

### Phase 2 — 거래 원장 (2~3주) ⭐ 핵심
- 주문 채번 (`ORDER-2026-000001`) + `기존관리번호` 필드
- 새 거래 등록 위저드 (4개 루트)
- 입금 / 입금 분해 / 예치금 원장
- 지출 / 지출 배분
- 주문 상세 + 마진 자동 계산 (**마진율 2종 병행 표시**)
- 정산완료 / 잠금 / 취소

### Phase 3 — 자금·송금 (1~2주)
- 자금현황 (실제 사용가능 자금)
- 해외송금 관리 (여러 주문 묶음 송금)
- **내부 자금이동** (신규)
- 계좌 잔액

### Phase 4 — 세무·운영비 (1~2주)
- 세금계산서 관리 (거래유형 기반, **발행여부 건별 플래그**)
- 중국 직원 급여 (**귀속월 필수**) / 임시공 / 사무실 경비

### Phase 5 — 대시보드·리포트 (1~2주)
- 메인 대시보드 (월별 전 지표, 내부 자금이동 별도 표시)
- 거래처별 순위 (내부 계정 제외)
- 거래처 상세
- 엑셀 내보내기

### Phase 6 — 마이그레이션·안정화 (2주) ⭐ 이 파일 전용 작업 포함
- 엑셀 가져오기 6단계
- **환율 수식 파싱기**
- **전각문자 기간 변환기**
- **거래처 별칭 병합 UI**
- **`이우드림` 내부 계정 분리**
- Sheet3 보류 데이터 화면
- 대조표 검증
- 실데이터 이관 + 1개월 병행 운영
- 백업 구성

**총 예상: 9~13주**

> Phase 2까지 끝나면 실제 거래 입력이 가능합니다. 그 시점부터 일부 업무를 옮겨 쓰면서 나머지를 붙이는 방식을 권합니다.

| 항목 | 답 |
|------|-----|
| 법인통장 부가세 방식 | **별도(EXCLUDED)** — M = 입금액 × 1.1, N = M/1.1로 확인 |
