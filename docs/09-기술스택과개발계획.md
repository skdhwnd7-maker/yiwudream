# 09. 기술스택 · 개발 계획

---

## 1. 기술스택 제안

| 영역 | 제안 | 이유 |
|------|------|------|
| 프레임워크 | **Next.js 15 (App Router) + TypeScript** | 한 프로젝트로 화면·API 동시 개발, 사내 배포 단순 |
| DB | **PostgreSQL 16** | `NUMERIC` 정확한 금액 계산, 트랜잭션·제약조건 강력 |
| ORM | **Prisma** | 타입 안전, 마이그레이션 관리, 감사 미들웨어 구현 용이 |
| UI | **Tailwind CSS + shadcn/ui** | 밀집형 표 화면에 적합 |
| 표/그리드 | **TanStack Table** | 정렬·필터·고정열·합계행 |
| 차트 | **Recharts** | 대시보드 추이·구성 |
| 엑셀 | **SheetJS(xlsx) + exceljs** | 가져오기/내보내기. **수식 문자열 읽기 필요** ⭐ |
| 인증 | **Auth.js (Credentials)** + bcrypt | 사내 계정, 외부 의존 없음 |
| 배포 | **Docker Compose** (app + postgres + nginx) | 사내 서버 1대로 운영 가능 |

> **엑셀 라이브러리 주의**: 이 파일은 환율이 수식(`=C3/218.22`)에만 있으므로, **수식 문자열을 읽을 수 있는 라이브러리**가 필수입니다. 값만 읽는 라이브러리를 쓰면 환율 정보를 못 가져옵니다.

**대안 (더 단순하게)**
- DB를 SQLite로 (직원 5명 이하, 단일 서버) → 백업이 파일 복사로 끝남
- 다만 동시 입력·대용량 집계는 PostgreSQL이 유리하므로 권장은 PostgreSQL

```ts
// ❌ 금지
const margin = 3492829.32 / 218.22        // float 오차

import { Decimal } from 'decimal.js'
const cny = new Decimal(krw).div(fxRate).toDecimalPlaces(2)
```

| 규칙 | 내용 |
|------|------|
| DB | `NUMERIC(18,2)` — `FLOAT`/`REAL` 금지 |
| 서버 | `Decimal.js` 또는 `Prisma.Decimal` |

## 3. 개발 단계

### Phase 0 — 설계 확정 ← **지금 여기**

- [x] 엑셀 원본 전 시트·전 수식 분석
- [x] 데이터베이스 구조 / 계산공식 / 화면 / 거래흐름 / 마이그레이션 설계
- [ ] **대표님 검토 및 확인 항목 회신** (아래 4장)

### Phase 1 — 기반 (1~2주)
- 프로젝트 셋업, DB 스키마 생성
- 로그인·권한
- 설정: 계좌 / 비용분류 / **거래유형** / 사용자
- 거래처 관리 + **별칭 병합 기능**
- **감사 미들웨어 (change_logs)** — 이후 모든 기능이 이 위에 얹힘

### Phase 2 — 거래 원장 (2~3주) ⭐ 핵심
- 주문 채번 (`ORDER-2026-000001`) + `기존관리번호` 필드
- 새 거래 등록 위저드 (4개 루트)
- 입금 / **입금 분해 (SALES·FEE·VAT·예치금)** / 예치금 원장
- 지출 / 지출 배분
- 주문 상세 + 마진 자동 계산 (**마진율 2종 병행 표시**)
- 정산완료 / 잠금 / 취소

### Phase 3 — 자금·송금 (1~2주)
- 자금현황 (실제 사용가능 자금 · **부가세 예수금** · **미수금**)
- 해외송금 관리 (여러 주문 묶음 송금)
- **내부 자금이동** (신규)
- 계좌 잔액

### Phase 4 — 세무·운영비 (1~2주)
- 세금계산서 관리 (거래유형 기반, **발행여부 건별 플래그**, **부가세 예수금 집계**, **미발행·부가세 수취 탭**)
- 중국 직원 급여 (**귀속월 필수**) / 임시공 / 사무실 경비

### Phase 5 — 대시보드·리포트 (1~2주)
- 메인 대시보드 (월별 전 지표, 내부 자금이동 별도 표시)
- 거래처별 순위 (내부 계정 제외)
- 거래처 상세
- 엑셀 내보내기

### Phase 6 — 마이그레이션·안정화 (2주) ⭐ 이 파일 전용 작업 포함
- 엑셀 가져오기 6단계 (Sheet2 · Sheet3 제외)
- **환율 수식 파싱기** (180종)
- **전각문자 기간 변환기**
- **거래처 별칭 병합 UI** (16그룹)
- **`이우드림` 내부 계정 분리** (16건)
- **에이스 미수금 주문 생성** (CNY 368,822)
- 대조표 검증
- 실데이터 이관 + 1개월 병행 운영
- 백업 구성

**총 예상: 9~13주**

> Phase 2까지 끝나면 실제 거래 입력이 가능합니다. 그 시점부터 일부 업무를 옮겨 쓰면서 나머지를 붙이는 방식을 권합니다.

## 4. 확인 항목 진행 상황

### ✅ 해결됨 (엑셀 분석 4건 + 대표님 회신 3건)

| 항목 | 답 | 출처 |
|------|-----|------|
| 법인통장 뒤쪽 부가세 열의 정체 | M = 합계금액(입금×1.1), N = 공급가액 → **부가세 별도** | 엑셀 수식 |
| 비용 열들의 통화 | **전부 CNY** | 마진 수식 구조 |
| 세금계산서 발행 범위 | 법인통장 483건 중 **114건(23.6%)** | M열 채움 현황 |
| 실제 적용환율 | **201.17 ~ 231.57 · 180종** (헤더 192/195는 무효) | D열 수식 파싱 |
| **Sheet3의 성격** | **무시해도 되는 데이터** → 가져오기 제외 | 대표님 회신 |
| **사이트 수수료 부가세** | **포함(INCLUDED)** → 100,000 = 공급가액 90,909 + 부가세 9,091 | 대표님 회신 |
| **예치금 기초잔액** | **없음** → 0에서 시작. 원장 구조는 사이트 루트용으로 유지 | 대표님 회신 |
| **에이스 CNY 368,822** | **미수금 확정** → `v_receivables`로 관리 | 대표님 회신 |
| **법인통장 C열·M열** | **C = 공급가액, M = 실제 입금액** → `receipt_splits`에 `VAT` 종류 신설 | 대표님 회신 |
| **미발행 369건 부가세** | **받고 계심** → 전 건 `VAT` 분해 생성. 부가세 예수금 115,507,964원 | 대표님 회신 |
| **일반통장 부가세** | **무관** → C열이 곧 실제 입금액. `VAT` 분해 없음 | 대표님 회신 |

### ⭐ "C열 = 공급가액" 확인으로 바뀐 것

가장 큰 구조 변경입니다. 입금 한 건 안에 성격이 다른 돈이 섞여 있다는 것이 확정됐습니다.

```
receipt_splits.split_kind 에 VAT 종류 신설

법인통장 3,456,960 = SALES 3,142,691 + VAT 314,269
사이트   1,100,000 = DEPOSIT_GOODS 1,000,000 + FEE 90,909 + VAT 9,091
```

| 바뀌는 것 | 내용 |
|-----------|------|
| 계좌 잔액 | 엑셀 기록보다 **115,507,964원 많습니다** (법인통장 4개월) |
| 마진·마진율 | **그대로**. 엑셀이 공급가액으로 환산해 계산한 것은 회계적으로 옳습니다 |
| 부가세 예수금 | **115,507,964원**이 실재합니다. 장부 어디에도 보이지 않던 돈입니다 |
| 입력 방식 | 직원은 **통장에 찍힌 금액**을 그대로 넣고, 프로그램이 공급가액·부가세로 쪼갭니다 |
| 적용 범위 | 법인통장 **전 건**(발행 114 + 미발행 369). 일반통장은 해당 없음 |

> 지난 턴에 "부가세를 못 받으신 게 아닌가" 여쭈었는데, **받으셨습니다.** 못 받은 돈은 없습니다.

#### 🔴 다만 하나 짚어드립니다

세금계산서를 발행하지 않고 받은 부가세가 **92,574,600원**입니다(369건).
받은 부가세는 신고·납부 의무가 따르고, 세금계산서 미발행은 별도 문제가 될 수 있습니다.
**세무사와 확인해 보시기를 권합니다.**

프로그램은 세무 판단을 하지 않습니다. 발행 여부와 무관하게 받은 부가세를 전부 집계하고,
`세금계산서 관리 > 미발행·부가세 수취` 탭에 목록과 금액을 보여드립니다.

### ⭐ "예치금 없음" 확인으로 새로 생긴 것

예치금이 0이면 일반통장의 CNY 264,329 차액은 갈 곳이 없습니다. 거래처별로 쪼개 확인한 결과:

```
에이스        입금 CNY 307,580  /  지출 CNY 649,052  →  −341,471   ← 원인
나머지 9곳    전부 흑자                                +77,142
```

에이스는 **입금 없는 지출만 44건, CNY 368,821.90** (약 8,100만원)입니다.
`해외송금·법인통장 어디에도 에이스는 없습니다` (교차 확인 완료).

→ **미수금(받을 돈)** 개념을 신설했습니다. 자금현황·거래처 화면에 표시하고 경과일로 관리합니다.
