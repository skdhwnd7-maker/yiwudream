# 03. 계산 공식

> 이 문서의 공식이 **프로그램의 유일한 계산 근거**입니다.
> 화면·리포트·엑셀 내보내기 모두 여기 정의된 식만 사용합니다.

---

## 0. 통화 환산 규칙

| 규칙 | 내용 |
|------|------|
| R-1 | 모든 금액 전표는 `원통화 금액` + `건별 적용환율` + `환산 KRW` + `환산 CNY`를 **저장 시점에 함께 확정**합니다. |
| R-2 | 환율이 나중에 바뀌어도 **과거 전표의 환산액은 절대 재계산하지 않습니다.** |
| R-3 | 환율 표기는 `KRW per 1 CNY` 기준 (예: 195.0 = 1위안당 195원) |
| R-4 | 반올림: KRW는 `settings.krw_rounding`(기본 FLOOR, 원 단위), CNY는 소수 둘째 자리 반올림 |

```
환산 CNY = 원통화가 KRW일 때  →  amount ÷ fx_rate
환산 KRW = 원통화가 CNY일 때  →  amount × fx_rate
USD 환산 →  usd_amount × fx_rate_krw_usd
```

> **해외송금 루트 주의:** USD 인보이스 금액은 통관 서류용 명목값이며, 마진은 **CNY 실제 도착금액** 기준으로만 계산합니다.

## 1. 주문(ORDER) 단위 계산 ⭐

### 1-1. 집계 정의

기준통화 `C` = `orders.settlement_currency` (해외송금=CNY, 그 외=KRW)

```
총입금(GROSS_IN)   = Σ receipts.amount_[C]          where order_id = 이 주문, is_void = false
수수료수입(FEE_IN)  = Σ receipt_splits.amount_[C]    where split_kind = 'FEE'
상품예치금(DEP_IN)  = Σ receipt_splits.amount_[C]    where split_kind = 'DEPOSIT_GOODS'
일반매출(SALES_IN) = Σ receipt_splits.amount_[C]    where split_kind = 'SALES'
```

비용은 분류별로 집계 (`expense_allocations` 를 통해 이 주문에 배분된 금액만):

```
상품비(COST_GOODS)     = Σ alloc_[C]  where category = GOODS
대행통관비(COST_CUSTOMS)= Σ alloc_[C]  where category = CUSTOMS
인건비(COST_LABOR)     = Σ alloc_[C]  where category IN (LABOR_CN, TEMP_LABOR)
검품비(COST_INSPECT)   = Σ alloc_[C]  where category = INSPECT
포장비(COST_PACKING)   = Σ alloc_[C]  where category = PACKING
운송비(COST_SHIPPING)  = Σ alloc_[C]  where category = SHIPPING
기타비(COST_ETC)       = Σ alloc_[C]  where category IN (ETC_ORDER, BANK_FEE)

총비용(TOTAL_COST) = COST_GOODS + COST_CUSTOMS + COST_LABOR
                   + COST_INSPECT + COST_PACKING + COST_SHIPPING + COST_ETC
```

### 1-2. 마진 — **거래유형의 `revenue_basis`에 따라 달라집니다** ⭐

#### ① `GROSS` (해외송금 / 일반통장 / 법인통장)

```
매출인식액 = 총입금(GROSS_IN)
최종마진   = 총입금 − 총비용
마진율(%)  = 최종마진 ÷ 총입금 × 100        (총입금 = 0 이면 0)
```

**예) 해외송금 (정산통화 CNY)**

| 항목 | 금액(CNY) |
|------|----------:|
| CNY 도착금액 | 25,000.00 |
| 상품지출 | −15,000.00 |
| 인건비 | −1,200.00 |
| 기타비 | −800.00 |
| **최종마진** | **8,000.00** |
| **마진율** | **32.00%** |

> 엑셀의 `마진 = CNY 도착금액 − 상품지출 − 인건비 − 기타비용` 과 동일하되,
> **여러 날짜에 나눠 발생한 지출이 모두 하나의 주문에 합산**된다는 점이 다릅니다.

#### ② `NET` (사이트 결제) ⭐

상품예치금은 **고객 돈이므로 매출이 아닙니다.**

```
매출인식액 = 수수료수입(FEE_IN)
최종마진   = 수수료수입 − 총비용_중_회사부담분
마진율(%)  = 최종마진 ÷ 수수료수입 × 100
```

여기서 `총비용_중_회사부담분`은 **상품대금(GOODS)을 제외한** 비용입니다.
상품대금은 예치금에서 나가는 돈이므로 회사 비용이 아닙니다.

```
회사부담비용 = TOTAL_COST − COST_GOODS_예치금충당분
```

**예) 사이트 결제**

| 항목 | 금액(KRW) |
|------|----------:|
| 총 입금액 | 1,100,000 |
| ├ 상품구매 예치금 | 1,000,000 *(매출 아님 — 부채)* |
| └ 구매대행 수수료 | 100,000 *(매출)* |
| 회사부담비용 (포장/기타) | −15,000 |
| **최종마진** | **85,000** |
| **마진율** | **85.00%** *(수수료 기준)* |

**동시에 예치금 흐름:**

| 항목 | 금액(KRW) |
|------|----------:|
| 총 상품자금 | 1,000,000 |
| 중국 송금완료 | 600,000 |
| **중국 송금대기** | **400,000** |

```
송금대기금(주문) = DEPOSIT_GOODS_IN − Σ remittance_allocations.alloc_krw (해당 주문)
```

### 1-3. 주문 송금 진행상태 (계산값)

```
송금완료액 = Σ remittance_allocations.alloc_krw  (status IN ('SENT','ARRIVED'))

송금완료액 = 0                    → 송금대기 (PENDING)
0 < 송금완료액 < 상품예치금        → 일부송금 (PARTIAL)
송금완료액 ≥ 상품예치금            → 송금완료 (DONE)
```

## 2. 거래처(PARTNER) 단위 계산

기준통화 = KRW (해외송금 CNY 금액은 전표의 `amount_krw`로 환산 저장값 사용)

| 항목 | 공식 |
|------|------|
| 누적 입금액 | `Σ receipts.amount_krw` (해당 거래처, is_void=false) |
| 누적 상품구매액 | `Σ expense_allocations.alloc_krw` where category = GOODS |
| 누적 인건비 | `Σ alloc_krw` where category IN (LABOR_CN, TEMP_LABOR) |
| 누적 통관비 | `Σ alloc_krw` where category = CUSTOMS |
| 누적 수수료 | `Σ receipt_splits.amount_krw` where split_kind = FEE |
| 누적 마진 | `Σ 주문별 최종마진(KRW)` |
| **현재 예치금** | `Σ deposit_ledger.amount_krw` (해당 거래처, 전체 kind) |
| **중국 송금대기금** | `Σ deposit_ledger.amount_krw` where deposit_kind = 'GOODS_FUND' |
| 미정산금 | `Σ 주문 총입금 − Σ 주문 총비용` where status = 'OPEN' → 진행중 주문의 미확정 금액 |
| 세금계산서 발행금액 | `Σ invoices.total_amount` where issue_status = 'ISSUED' |
| 세금계산서 발행예정 | `Σ invoices.total_amount` where issue_status = 'PENDING' |

## 3. 자금현황 계산 ⭐ (가장 중요한 화면)

> **핵심: 통장에 있는 돈 ≠ 회사 돈**

```
① 전체 계좌잔액
   = Σ accounts.opening_balance
   + Σ receipts.amount            (해당 계좌 입금)
   − Σ expenses.amount            (해당 계좌 출금, payment_status = 'PAID')
   − Σ remittances.krw_amount     (해당 출금계좌)
   − Σ remittances.bank_fee_krw
   ※ 계좌 통화별로 계산 후 KRW 환산 합계 (entity 별 소계 병행 표시)

② 고객 예치금 (부채)
   = Σ deposit_ledger.amount_krw            -- 전 거래처 합계

③ 중국 송금대기금
   = Σ deposit_ledger.amount_krw  where deposit_kind = 'GOODS_FUND'
   ※ ③ 은 ② 의 부분집합입니다 (중복 차감 금지)

④ 회사 수수료 (미정산 수익)
   = Σ receipt_splits.amount_krw  where split_kind = 'FEE'
     and 소속 주문 status = 'OPEN'

⑤ 미정산 비용 (미지급금)
   = Σ expenses.amount_krw  where payment_status = 'PLANNED' and is_void = false

⑥ 실제 사용가능 자금  ⭐
   = ① 전체 계좌잔액  −  ② 고객 예치금  −  ⑤ 미정산 비용
```

**예시 (요구사항의 시나리오)**

| 항목 | 금액 |
|------|-----:|
| ① 전체 계좌잔액 | 100,000,000 |
| ② 고객 예치금 | 80,000,000 |
| ③ ㄴ 중 중국 송금대기금 | 65,000,000 |
| ⑤ 미정산 비용 | 0 |
| **⑥ 실제 사용가능 자금** | **20,000,000** |

> 화면에는 ⑥을 가장 크게, ②·③을 경고색(주황/빨강)으로 표시합니다.

## 4. 세금계산서 계산 ⭐ (거래유형 설정 기반, 하드코딩 금지)

### 4-1. 발행대상금액 (`target_amount`)

`deal_types.invoice_base` 값에 따라 결정:

| invoice_base | target_amount |
|--------------|---------------|
| `NONE` | 0 (발행 대상 아님) |
| `TOTAL_RECEIPT` | 주문 총입금액 (KRW) |
| `FEE_ONLY` | 수수료수입 합계 (`split_kind = FEE`) |
| `CUSTOMS_ONLY` | 대행통관비 합계 |
| `MARGIN` | 주문 최종마진 |
| `MANUAL` | 담당자 직접 입력 |

> 자동 산출값을 담당자가 수정하면 `target_amount_source = 'MANUAL'` 로 바뀌고 **사유 입력이 필수**이며 변경이력에 남습니다.

### 4-2. 공급가액 / 부가세 / 합계

`deal_types.vat_mode` 에 따라:

```
[INCLUDED] 부가세 포함 금액이 대상금액인 경우
   공급가액 = ROUND_RULE( target_amount ÷ (1 + vat_rate) )
   부가세   = target_amount − 공급가액
   합계     = target_amount

[EXCLUDED] 부가세 별도인 경우
   공급가액 = target_amount
   부가세   = ROUND_RULE( target_amount × vat_rate )
   합계     = 공급가액 + 부가세

[EXEMPT] 면세
   공급가액 = target_amount,  부가세 = 0,  합계 = target_amount

[ZERO] 영세율 (수출)
   공급가액 = target_amount,  부가세 = 0,  합계 = target_amount
```

`ROUND_RULE` = `deal_types.rounding` (`ROUND`/`FLOOR`/`CEIL`, 원 단위)

**예) 사이트 수수료 100,000원**

| vat_mode | 공급가액 | 부가세 | 합계 |
|----------|--------:|------:|-----:|
| INCLUDED (포함) | 90,909 | 9,091 | 100,000 |
| EXCLUDED (별도) | 100,000 | 10,000 | 110,000 |

> ⚠️ 어느 쪽으로 할지는 **대표님이 설정으로 지정**합니다. 프로그램이 임의 확정하지 않습니다.

### 4-3. 회계분류는 별도 기록

`accounting_class`(용역매출 / 상품매출 / 중개수수료 / 해외매출 / 매출아님)는
`invoice_base`와 **독립적으로** 저장됩니다.
→ "세금계산서를 안 끊어도 회계상 매출", "세금계산서는 끊지만 순액매출" 같은 케이스를 모두 표현할 수 있습니다.

## 5. 대시보드 월별 지표

기간: `[월초, 월말]`, 기준일 = 전표의 발생일(`receipt_date` / `expense_date` / `remit_date`)

| 지표 | 공식 |
|------|------|
| 총 거래액 | `Σ receipts.amount_krw` (전 루트) |
| 해외송금 거래액 | ↑ where route = `OVERSEAS` |
| 일반통장 거래액 | ↑ where route = `BANK_GEN` |
| 법인통장 거래액 | ↑ where route = `BANK_CORP` |
| 사이트 거래액 | ↑ where route = `SITE` |
| 총 상품구매액 | `Σ expenses.amount_krw` where category = GOODS |
| 대행통관 수익 | `Σ 주문마진` where deal_type.code = `CORP_CUSTOMS` *(또는 통관 전용 거래유형)* |
| 구매대행 수수료 | `Σ receipt_splits.amount_krw` where split_kind = FEE |
| 인건비 수익 | `Σ (인건비 청구액 − 인건비 지출액)` — 인건비를 고객에게 청구하는 거래유형에 한함 ⚠️확인필요 |
| 기타 수익 | 위 분류에 속하지 않는 주문마진 합계 |
| **중국 운영비** | `Σ expenses.amount_krw` where category.cost_type = OPERATING **and 주문 미귀속** |
| ├ 직원 급여 | ↑ where category IN (SALARY, INSURANCE) |
| ├ 임시공 비용 | ↑ where category = TEMP_LABOR and 주문 미귀속 |
| └ 사무실 경비 | ↑ where category = OFFICE |
| **최종 영업마진** | `Σ 주문별 최종마진 − 중국 운영비` |
| 마진율 | `최종 영업마진 ÷ 총 매출인식액 × 100` |
| 고객 예치금 | 월말 시점 `Σ deposit_ledger` |
| 중국 송금대기금 | 월말 시점 `Σ deposit_ledger where GOODS_FUND` |
| 세금계산서 발행예정금 | `Σ invoices.total_amount where issue_status = PENDING` |
| 세금계산서 발행완료금 | `Σ invoices.total_amount where issue_status = ISSUED` |

**거래처별 순위**
```sql
-- 매출 TOP 10 / 마진 TOP 10
SELECT p.name,
       SUM(매출인식액)  AS revenue,
       SUM(최종마진)    AS margin,
       SUM(최종마진) / NULLIF(SUM(매출인식액),0) * 100 AS margin_rate
FROM orders o JOIN partners p ON p.id = o.partner_id
WHERE o.order_date BETWEEN :from AND :to AND o.is_void = FALSE
GROUP BY p.name
ORDER BY margin DESC LIMIT 10;
```

## 6. 계좌 잔액 계산

```
계좌잔액(account_id, 기준일)
 = opening_balance
 + Σ receipts.amount        where account_id = A and receipt_date ≤ 기준일 and not void
 − Σ expenses.amount        where account_id = A and paid_at     ≤ 기준일 and payment_status='PAID' and not void
 − Σ remittances.krw_amount where from_account_id = A and remit_date ≤ 기준일 and status ≠ 'CANCELLED'
 − Σ remittances.bank_fee_krw where from_account_id = A and ...
 + Σ remittances.cny_arrival_amount where to_account_id = A and status = 'ARRIVED'   -- 중국 수취계좌
```

## 7. 검증 규칙 (입력 시 경고)

| 코드 | 조건 | 처리 |
|------|------|------|
| W-01 | 마진율 < 0 | 경고 후 저장 가능 (사유 입력 권장) |
| W-02 | 마진율 > 60% | 확인 팝업 ("입력 실수 아닌가요?") |
| W-03 | 예치금 잔액이 음수가 됨 | 저장 차단 (MANAGER 이상 승인 시 허용) |
| W-04 | 적용환율이 최근 30일 평균 대비 ±10% 이탈 | 경고 표시 |
| W-05 | 송금 배분 합계 ≠ 송금액 | 저장 차단 |
| W-06 | 입금 분해 합계 ≠ 입금액 | 저장 차단 |
| W-07 | 지출 배분 합계 > 지출액 | 저장 차단 |
| W-08 | 정산완료 주문에 전표 추가 시도 | 차단 (잠금해제 필요) |
