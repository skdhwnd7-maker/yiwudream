# 06. 엑셀 마이그레이션

> ⚠️ **중요**: 이번 세션에 엑셀 원본 파일이 전달되지 않았습니다.
> 아래 매핑은 대표님이 설명해 주신 **항목명 기준의 잠정안**입니다.
> 파일을 다시 첨부해 주시면 실제 컬럼 위치·데이터 상태를 분석해 매핑표를 확정하겠습니다.

---

## 1. 마이그레이션 원칙

| # | 원칙 | 이유 |
|---|------|------|
| 1 | **원본 행을 통째로 보존** (`import_rows.raw_json`) | 나중에 "엑셀 몇 번째 줄이 어디로 갔나" 역추적 가능 |
| 2 | **1행 = 1주문** 으로 먼저 생성 후, 필요 시 병합 | 자동 추론으로 잘못 묶는 것보다 안전 |
| 3 | **배치 단위 롤백** | 잘못 들어가면 그 배치 전체를 되돌림 |
| 4 | **애매한 데이터는 버리지 않고 `HOLD`** | 특히 Sheet3. 담당자 확인 후 반영 |
| 5 | **마이그레이션 주문은 별도 표시** (`ORDER-MIG-...`) | 신규 거래와 구분 |
| 6 | **환율은 원본 값 그대로**, 없으면 `HOLD` | 임의 환율 생성 금지 |

---

## 2. 가져오기 5단계

```
STEP 1  업로드        .xlsx 업로드 → import_batches 생성 (status=UPLOADED)
STEP 2  시트 감지     시트명/헤더 자동 인식 → 처리 대상 선택
STEP 3  컬럼 매핑     원본 컬럼 → 시스템 필드 (자동 추천, 수동 수정 가능, 매핑 저장)
STEP 4  검증 미리보기  ✅정상 / ⚠️경고 / ❌오류 / ⏸보류 건수 + 상세 사유
STEP 5  실행          트랜잭션으로 일괄 생성 (status=COMMITTED) / [배치 되돌리기] 가능
```

## 3. 시트별 변환 계획

### 3-1. `해외송금` 시트 → 해외송금 루트 주문

| 엑셀 컬럼 | 대상 테이블.필드 | 변환 규칙 |
|-----------|-----------------|----------|
| 일자 | `orders.order_date`, `receipts.receipt_date` | |
| 거래처 | `orders.partner_id` | 거래처명으로 매칭, 없으면 **신규 자동 생성** |
| USD 이보이스 금액 | `receipts.usd_amount`, `orders.usd_invoice_amount` | 참고값 (마진 계산 미사용) |
| CNY 실제 도착금액 | `receipts.amount` (CNY), `receipt_splits.SALES` | **마진 기준값** |
| CNY 상품 지출금액 | `expenses`(GOODS, CNY) + `expense_allocations` | 0이면 행 생성 안 함 |
| 인건비용 | `expenses`(LABOR_CN, CNY) + 배분 | |
| 기타비용 | `expenses`(ETC_ORDER, CNY) + 배분 | |
| 마진 | — | **가져오지 않음.** 재계산값과 대조만 수행 |
| 마진율 | — | 동일 |

**고정값**: `route=OVERSEAS`, `entity=CN`, `settlement_currency=CNY`, `deal_type=OVERSEAS_DIRECT`

**검증**: `원본 마진 ≠ 재계산 마진` 인 행은 ⚠️경고 목록에 표시 (대부분 반올림 차이, 일부는 원본 수식 오류 발견 가능)

---

### 3-2. `일반통장` 시트 → 일반통장 루트 주문

| 엑셀 컬럼 | 대상 | 변환 규칙 |
|-----------|------|----------|
| 일자 | `orders.order_date` / `receipts.receipt_date` | |
| 거래처 | `orders.partner_id` | |
| KRW 입금액 | `receipts.amount` (KRW) | |
| 적용환율 | `receipts.fx_rate` | **행별 값 그대로**. 비어있으면 ⏸`HOLD` |
| 환산 CNY | `receipts.amount_cny` | 원본 값 사용, 없으면 `입금액 ÷ 환율` |
| CNY 지출금액 | `expenses`(GOODS, CNY) + 배분 | |
| 대행통관비 | `expenses`(CUSTOMS) + 배분 | 통화 판별 필요 ⚠️ |
| 인건비 | `expenses`(LABOR_CN) + 배분 | |
| 기타비 | `expenses`(ETC_ORDER) + 배분 | |
| 마진 / 마진율 | — | 대조용으로만 사용 |

**고정값**: `route=BANK_GEN`, `entity=KR`, `settlement_currency=KRW`, `deal_type=GEN_DEPOSIT`

**추가 처리 — 예치금 기초 이월** ⭐
- 엑셀상 "입금만 있고 지출이 없는 행"은 **예치금 적립**으로 처리할지 담당자가 선택
  - 선택 A: 주문 생성 (매출로 인식)
  - 선택 B: `deposit_ledger` `IN_RECEIPT` 만 생성 (주문 없음)
- 마이그레이션 시점의 **거래처별 예치금 잔액을 담당자가 직접 입력**하여 `ADJUST` 행으로 기초 세팅하는 방식도 지원 (권장)

---

### 3-3. `법인통장` 시트 → 법인통장 루트 주문

| 엑셀 컬럼 | 대상 | 변환 규칙 |
|-----------|------|----------|
| 거래처 | `orders.partner_id` | |
| 입금금액 | `receipts.amount` (KRW) | |
| 적용환율 | `receipts.fx_rate` | |
| CNY 환산금액 | `receipts.amount_cny` | |
| 중국 상품비 | `expenses`(GOODS) + 배분 | |
| 대행통관비 | `expenses`(CUSTOMS) + 배분 | |
| 인건비 | `expenses`(LABOR_CN) + 배분 | |
| 기타비 | `expenses`(ETC_ORDER) + 배분 | |
| 마진/마진율 | — | 대조용 |
| **뒤쪽 부가세 관련 열 (헤더 불명확)** ⚠️ | `invoices.*` | 아래 별도 처리 |

**부가세 열 처리 방안** ⚠️확인필요

원본 파일 확인 후 다음 중 하나로 매핑합니다.

| 원본 값이 | 매핑 |
|-----------|------|
| 공급가액 성격 (입금액 ÷ 1.1) | `invoices.supply_amount` |
| 부가세 성격 (입금액 ÷ 11) | `invoices.vat_amount` |
| 합계 성격 (= 입금액) | `invoices.total_amount` |
| 발행일/발행여부 | `invoices.issue_date` / `issue_status` |

→ 매핑 STEP 3 화면에서 **샘플 3행의 실제 값과 입금액의 비율을 자동 계산해 추천**합니다.
  (예: `열E ÷ 입금액 = 0.9091` → "공급가액으로 추정됩니다")

**고정값**: `route=BANK_CORP`, `entity=KR`, `deal_type=CORP_FULL`

### 3-4. `Sheet1` → 중국 운영비

한 시트에 급여 / 사회보험 / 임시공 / 사무실경비가 섞여 있음 → **4개로 분리**

| 원본 내용 | 대상 | 판별 기준 |
|-----------|------|----------|
| 직원 월급 | `employees` + `payrolls` + `expenses`(SALARY) | 직원명 컬럼 존재, 월 단위 반복 |
| 사회보험 (社保) | `payrolls.insurance_*` + `expenses`(INSURANCE) | 항목명에 `社保`/`사회보험` 포함 |
| 임시공 비용 (临时工费用) | `expenses`(TEMP_LABOR) | 항목명에 `临时工`/`임시공` 포함 |
| 사무실 경비 | `expenses`(OFFICE) | 그 외 (임차료/수도광열/사무용품 등) |

**처리 순서**
1. 원본 행을 규칙으로 자동 분류 → 미리보기에서 **분류 결과를 담당자가 검수/수정**
2. 직원명은 `employees` 마스터로 승격 (중복 제거)
3. 임시공 행의 **귀속 주문은 비워둔 채로 가져옴** (과거 데이터는 귀속 정보가 없음) → 전부 운영비 처리
   - 필요 시 나중에 주문 연결 가능

**고정값**: `entity=CN`, `currency=CNY`

### 3-6. `Sheet3` → ⏸ 보류(HOLD) 테이블로만 가져옴 ⚠️

**문제**: 거래처별 금액이 있으나 CNY / USD / KRW가 혼재 → 의미 불명.

**처리 방안**
1. 전 행을 `import_rows`에 `HOLD` 상태로 적재 (원본 그대로)
2. 별도 화면 `엑셀 가져오기 > 보류 데이터`에서 담당자가 행별로 지정:
   - 통화 (CNY / USD / KRW)
   - 성격 → 아래 중 선택

| 추정 성격 | 반영 방법 |
|-----------|----------|
| 거래처별 **미수금** | 담당자 확인 후 `orders` 미정산 잔액으로 반영 |
| 거래처별 **예치금 잔액** | `deposit_ledger` `ADJUST` 기초행 생성 |
| 거래처별 **누적 거래액 요약** | 참고용 메모로만 보관 (원장 반영 안 함) |
| 의미 없음 | `SKIP` |

3. 확정 전까지는 **어떤 집계에도 반영되지 않습니다.**

> 📌 **대표님 확인 요청**: Sheet3의 숫자가 위 중 무엇인지 알려주시면 자동 변환 규칙을 만들 수 있습니다.

## 4. 거래처 마스터 생성

1. 4개 시트의 거래처명을 전부 수집 → 중복 제거
2. 표기 흔들림 정규화 (공백/(주)/㈜/영문 대소문자)
3. 유사 이름은 **병합 후보**로 제시 → 담당자 확인 후 병합
4. 거래처 코드 자동 채번 (`P0001`~)
5. `default_route` = 그 거래처가 가장 많이 등장한 시트의 루트로 자동 설정

## 5. 검증 리포트 (STEP 4에서 표시)

| 검증 항목 | 결과 처리 |
|-----------|----------|
| 필수값(일자/거래처/금액) 누락 | ❌ 오류 — 가져오지 않음 |
| 숫자 셀에 문자 포함 | ❌ 오류 |
| 환율 누락인데 KRW→CNY 환산 필요 | ⏸ 보류 |
| 원본 마진 ≠ 재계산 마진 (±1 초과) | ⚠️ 경고 — 가져오되 목록 제공 |
| 거래처명 신규 | ⚠️ 경고 — 신규 생성 예정 표시 |
| 날짜 형식 이상 | ⚠️ 경고 — 추정 변환 후 표시 |
| 마진율 음수 | ⚠️ 경고 |
| 중복 의심 행 (동일 일자+거래처+금액) | ⚠️ 경고 — 체크 해제 가능 |

**가져오기 완료 후 대조표 제공**

```
              엑셀 원본 합계      시스템 합계        차이
해외송금      CNY  1,240,000    CNY  1,240,000        0  ✓
일반통장      KRW 312,000,000   KRW 312,000,000       0  ✓
법인통장      KRW 401,000,000   KRW 400,998,000   -2,000  ⚠️ (반올림 3건)
Sheet1(운영비) CNY   139,200    CNY   139,200         0  ✓
```

## 6. 마이그레이션 이후 권장 순서

```
1. 엑셀 가져오기 (과거 데이터)
2. 계좌 기초잔액 입력 (accounts.opening_balance)
3. 거래처별 예치금 기초잔액 입력 → deposit_ledger ADJUST
4. 거래유형(deal_types) 세무 규칙 확정 ⚠️ 대표님 결정 필요
5. 대조표로 엑셀 vs 시스템 금액 일치 확인
6. 신규 거래는 시스템에만 입력 (엑셀 병행 1개월 → 이후 중단)
```
