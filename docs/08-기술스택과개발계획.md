# 08. 기술스택 · 개발 계획

---

## 1. 기술스택 제안

| 영역 | 제안 | 선택 이유 |
|------|------|----------|
| 프레임워크 | **Next.js 15 (App Router) + TypeScript** | 한 프로젝트로 화면·API 동시 개발, 사내 배포 단순 |
| DB | **PostgreSQL 16** | `NUMERIC` 정확한 금액 계산, 트랜잭션·제약조건 강력, 무료 |
| ORM | **Prisma** | 타입 안전, 마이그레이션 관리, 감사 미들웨어 구현 용이 |
| UI | **Tailwind CSS + shadcn/ui** | PC 밀집형 표 화면에 적합, 한글 폰트 대응 |
| 표/그리드 | **TanStack Table** | 정렬/필터/고정열/합계행 |
| 차트 | **Recharts** | 대시보드 추이·구성 차트 |
| 엑셀 | **SheetJS(xlsx)** | 가져오기/내보내기 |
| 인증 | **Auth.js (Credentials)** + bcrypt | 사내 계정, 외부 의존 없음 |
| 배포 | **Docker Compose** (app + postgres + nginx) | 사내 서버 1대로 운영 가능 |

**대안 (더 단순하게 원하실 경우)**
- DB를 SQLite로 (직원 5명 이하, 단일 서버) → 백업이 파일 복사로 끝남
- 다만 동시 입력·대용량 집계에서 PostgreSQL이 유리하므로 **PostgreSQL 권장**

> ⚠️ 스택은 확정 전입니다. 기존에 쓰시는 서버/호스팅 환경이 있으면 알려주세요.

## 2. 금액 처리 규칙 (구현 필수)

```ts
// ❌ 절대 금지
const margin = 1100000 * 0.1        // float 오차

// ✅ 필수
import { Decimal } from 'decimal.js'
const margin = new Decimal(receipt).minus(cost)
```

| 규칙 | 내용 |
|------|------|
| DB | `NUMERIC(18,2)` — `FLOAT`/`REAL` 금지 |
| 서버 | `Decimal.js` 또는 `Prisma.Decimal` |
| 클라이언트 | 문자열로 전달, 표시 직전에만 포맷 |
| 반올림 | 계산 중간에 반올림하지 않고 **최종 표시/저장 시 1회만** |

## 3. 개발 단계 (권장 순서)

### Phase 0 — 설계 확정 ← **지금 여기**
- [x] 업무 분석 / DB 설계 / 계산공식 / 화면 / 마이그레이션 문서화
- [ ] **대표님 검토 및 확인 항목 회신** (아래 4장)
- [ ] 엑셀 원본 파일 확보 후 매핑표 확정

### Phase 1 — 기반 (1~2주)
- 프로젝트 셋업, DB 스키마 생성
- 로그인/권한
- 설정 화면: 계좌 / 비용분류 / **거래유형** / 사용자
- 거래처 관리 (목록·등록·수정)
- **감사 미들웨어 (change_logs)** — 이후 모든 기능이 이 위에 얹힘

### Phase 2 — 거래 원장 (2~3주) ⭐ 핵심
- 주문 채번·생성
- 새 거래 등록 위저드 (4개 루트 전부)
- 입금 / 입금 분해 / 예치금 원장
- 지출 / 지출 배분
- 주문 상세 화면 + 마진 자동 계산
- 정산완료 / 잠금 / 취소

### Phase 3 — 자금·송금 (1~2주)
- 자금현황 화면 (실제 사용가능 자금)
- 해외송금 관리 (송금대기 목록, 여러 주문 묶음 송금)
- 계좌 잔액 계산

### Phase 4 — 세무·운영비 (1~2주)
- 세금계산서 관리 (거래유형 기반 자동 산출)
- 중국 직원 급여 / 임시공 / 사무실 경비

### Phase 5 — 대시보드·리포트 (1~2주)
- 메인 대시보드 (월별 전 지표)
- 거래처별 순위
- 거래처 상세 대시보드
- 엑셀 내보내기

### Phase 6 — 마이그레이션·안정화 (1~2주)
- 엑셀 가져오기 (5단계 위저드)
- 대조표·검증 리포트
- 실데이터 이관 + 1개월 병행 운영
- 백업 구성

**총 예상: 8~12주** (요구사항 변경 여지 포함)

## 4. ⚠️ 대표님 확인 필요 항목 (개발 착수 전 회신 요청)

| # | 항목 | 필요한 결정 |
|---|------|------------|
| 1 | **엑셀 원본 파일** | 재첨부 부탁드립니다. 컬럼 매핑 확정에 필요합니다. |
| 2 | **Sheet3의 의미** | 거래처별 ①미수금 ②예치금 잔액 ③누적 거래액 요약 중 무엇인가요? 통화는 행마다 다른가요? |
| 3 | **사이트 수수료 부가세** | 수수료 10만원이 부가세 **포함**인가요, **별도**인가요? |
| 4 | **해외송금 세무 처리** | 중국법인 매출로 보나요, 한국법인 용역매출로 보나요? (회계분류 기본값 결정) |
| 5 | **"인건비 수익"의 의미** | 고객에게 인건비를 마진 붙여 청구하시나요? 그렇다면 청구액과 실지출을 따로 입력받아야 합니다. |
| 6 | **대행통관 수익 산정** | 통관비를 고객에게 받는 금액과 실제 통관 지출을 따로 관리하시나요? |
| 7 | **일반통장 예치금 기초** | 현재 거래처별 예치금 잔액을 알고 계신가요? (마이그레이션 기초값) |
| 8 | **사용 인원/권한** | 직원 몇 명이 쓰나요? 직원이 마진·급여를 볼 수 있어야 하나요? |
| 9 | **서버 환경** | 사내 서버 / 클라우드(AWS·NCP) / 기존 호스팅 중 어디에 두실 건가요? |
| 10 | **동시 사용 국가** | 중국 현지 직원도 접속하나요? (중국에서의 접속 속도·차단 고려 필요) |
