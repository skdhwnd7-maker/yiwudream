# 03. 데이터베이스 설계

## 0. 설계 규칙

| 규칙 | 내용 |
|------|------|
| 금액 타입 | `NUMERIC(18,2)` — 부동소수점 금지 |
| 환율 타입 | `NUMERIC(18,6)` — **건별 저장**. 엑셀처럼 수식에 숨기지 않음 |
| 삭제 | **물리 삭제 금지.** `is_void` + 취소사유 |
| 이력 | 금액성 테이블 전부 `change_logs`에 필드 단위 기록 |
| 시각 | 모든 테이블 `created_at / created_by / updated_at / updated_by` |
| 자금주체 | `entity` = `KR` / `CN` — 혼합 집계 금지 |
| 통화 | 원통화 금액 + 적용환율 + 환산액(KRW·CNY) 모두 저장 |

**초기 데이터 — 엑셀 분석으로 확정된 값**

| code | name | revenue_basis | invoice_base | invoice_default | vat_mode | accounting_class |
|------|------|--------------|--------------|:---------------:|----------|------------------|
| `OVERSEAS_DIRECT` | 해외송금 직접거래 | GROSS | NONE | ✗ | EXEMPT | 해외매출 |
| `GEN_DEPOSIT` | 일반통장 예치정산 | GROSS | MANUAL | ✗ | INCLUDED | 용역매출 |
| `CORP_FULL` | 법인통장 전액발행 | GROSS | TOTAL_RECEIPT | ✓ | **EXCLUDED** ⭐ | 상품매출 |
| `CORP_NOBILL` | 법인통장 미발행 | GROSS | NONE | ✗ | **EXCLUDED** ⭐ | 상품매출 |
| `CORP_CUSTOMS` | 대행통관 용역 | GROSS | CUSTOMS_ONLY | ✓ | EXCLUDED | 용역매출 |
| `SITE_AGENCY` | 사이트 구매대행 | **NET** | **FEE_ONLY** | ✓ | **INCLUDED** ⭐ | 중개수수료 |

> **`CORP_NOBILL`의 `vat_mode`도 `EXCLUDED`인 이유**: 세금계산서만 발행하지 않을 뿐
> **부가세는 받고 계십니다**(대표님 확인). 따라서 입금 분해에 `VAT`가 동일하게 생깁니다.
>
> **`CORP_FULL`의 `vat_mode`를 `EXCLUDED`로 확정한 근거**: 법인통장 M열 = 입금액 × 1.1 (114건 중 113건이 정확히 1.1배), N열 = `=M/1.1`. 즉 입금액 자체가 공급가액이고 부가세가 별도로 붙습니다.
>
> **`CORP_NOBILL`을 신설한 근거**: 법인통장 입금 483건 중 M열에 값이 있는 건 114건(23.6%)뿐입니다. 나머지 369건은 세금계산서를 발행하지 않았습니다.
>
> **`SITE_AGENCY`의 `vat_mode`를 `INCLUDED`로 확정**: 대표님 확인 결과 사이트 수수료는 **부가세 포함** 금액입니다.
> 수수료 100,000원 → 공급가액 90,909 / 부가세 9,091 / 합계 100,000.
>
> ⚠️ **파생 논점**: 부가세 9,091원은 국세청에 낼 돈이지 회사 수익이 아닙니다.
> 고객 예치금과 같은 성격(남의 돈)이므로 **마진은 공급가액 기준**으로 계산하고,
> 부가세는 `부가세 예수금`으로 자금현황에 별도 표시합니다. (`settings.margin_vat_basis`로 변경 가능, 기본 `SUPPLY`)

### 3-3. `receipt_splits` — 입금 성격 분해 ⭐⭐ (이 설계의 핵심)

> **입금 한 건에 성격이 다른 돈이 섞여 들어옵니다.** 이걸 쪼개 저장하는 것이
> 「회사 돈과 남의 돈을 구분한다」는 요구를 실제로 구현하는 자리입니다.

| 컬럼 | 설명 |
|------|------|
| id / receipt_id | |
| split_kind | `SALES` / `FEE` / **`VAT`** / `DEPOSIT_GOODS` / `DEPOSIT_GENERAL` |
| amount / amount_krw / amount_cny | |

**제약: `SUM(splits.amount) = receipts.amount`** (DB 트리거)

#### split_kind — 누구 돈인가로 나눕니다

| 종류 | 의미 | 누구 돈 | 매출 | 마진 계산 |
|------|------|---------|:----:|:--------:|
| `SALES` | 상품·용역 공급가액 | **회사** | ● | ● |
| `FEE` | 구매대행 수수료 공급가액 | **회사** | ● | ● |
| **`VAT`** ⭐ | 받은 부가세 | **국세청** | ✗ | ✗ |
| `DEPOSIT_GOODS` | 상품구매 예치금 | **고객** | ✗ | ✗ |
| `DEPOSIT_GENERAL` | 용도미지정 예치금 | **고객** | ✗ | ✗ |

> **`VAT` 종류를 새로 만든 이유**: 대표님 확인 결과 법인통장 C열은 공급가액이고
> **실제 입금액은 M열(= C × 1.1)** 이었습니다. 사이트 수수료도 부가세 포함입니다.
> 즉 두 루트 모두 입금액 안에 부가세가 섞여 들어옵니다.
> `receipts.amount`에는 **실제 입금액**을 넣고, 그 안의 부가세를 `VAT` 분해로 떼어냅니다.

#### 루트별 기본 분해

| 루트 | 분해 | 예시 | 근거 |
|------|------|------|------|
| `BANK_CORP` (발행) | `SALES` + `VAT` | 3,456,960 = 3,142,691 + 314,269 | M열 실측 |
| `BANK_CORP` (미발행) | `SALES` + `VAT` | 입금 = 공급가액 × 1.1 | 대표님 확인 ⭐ |
| `SITE` | `DEPOSIT_GOODS` + `FEE` + `VAT` | 1,100,000 = 1,000,000 + 90,909 + 9,091 | 수수료 부가세 포함 |
| `BANK_GEN` (주문 미지정) | `DEPOSIT_GENERAL` 100% | | 부가세 무관 ⭐ |
| `BANK_GEN` (주문 지정) | `SALES` 100% | C열이 곧 입금액 | 부가세 무관 ⭐ |
| `OVERSEAS` | `SALES` 100% | | 해외거래 |

> **법인통장은 세금계산서 발행 여부와 무관하게 전 건 `VAT` 분해가 생깁니다.**
> 발행하지 않은 369건도 부가세를 받고 계시기 때문입니다(대표님 확인).
> 그래서 부가세 예수금을 `invoices`가 아니라 **`receipt_splits`에서 집계**합니다 — 미발행분이 누락되지 않습니다.
>
> **일반통장은 `VAT` 분해가 생기지 않습니다.** 부가세와 무관한 거래입니다.

#### 이 구조가 자동으로 만들어 주는 것

```
계좌 잔액       = Σ receipts.amount                   ← 실제 통장 금액과 일치
매출인식액      = Σ splits (SALES + FEE)              ← 부가세·예치금 제외
부가세 예수금    = Σ splits (VAT)                      ← 국세청에 낼 돈
고객 예치금      = Σ splits (DEPOSIT_*)                ← 고객 돈
실제 사용가능 자금 = 잔액 − 예치금 − 부가세 − 미지급
```

### 4-1. `remittances` — 고객자금 송금 전표

## 8-2. 계산 뷰 (신규) ⭐

테이블이 아니라 **뷰**입니다. 저장된 값이 아니라 원장에서 항상 다시 계산됩니다.

### `v_receivables` — 미수금 (받을 돈)

> 에이스 CNY 368,822처럼 **지출은 나갔는데 입금이 없는 금액**을 잡습니다.

```sql
CREATE VIEW v_receivables AS
SELECT o.id AS order_id, o.partner_id, o.order_no, o.settlement_currency,
       COALESCE(inc.total, 0)                       AS received,
       COALESCE(cost.total, 0)                      AS spent,
       COALESCE(cost.total,0) - COALESCE(inc.total,0) AS receivable   -- 양수면 받을 돈
FROM orders o
LEFT JOIN (…입금 합계…) inc  ON inc.order_id  = o.id
LEFT JOIN (…배분 지출 합계…) cost ON cost.order_id = o.id
WHERE o.is_void = FALSE AND o.status = 'OPEN'
  AND COALESCE(cost.total,0) > COALESCE(inc.total,0);
```

거래처별 미수금은 이 뷰를 `partner_id`로 묶습니다.

### `v_vat_payable` — 부가세 예수금 (낼 돈)

> 고객에게 **실제로 받아서 갖고 있는** 부가세. 국세청에 낼 돈이므로 회사 돈이 아닙니다.

```sql
-- 세금계산서가 아니라 '받은 돈'에서 집계합니다.
-- 계산서를 발행하지 않고 받은 부가세도 빠짐없이 잡기 위해서입니다.
CREATE VIEW v_vat_payable AS
SELECT date_trunc('month', r.receipt_date) AS period,
       SUM(s.amount_krw)                   AS vat_received
FROM receipt_splits s
JOIN receipts r ON r.id = s.receipt_id
WHERE s.split_kind = 'VAT' AND r.is_void = FALSE
GROUP BY 1;
```

**엑셀 4개월 기준 115,507,964원**입니다.

| 구분 | 건수 | 부가세 |
|------|----:|------:|
| 세금계산서 발행 | 114 | 22,933,364 |
| 세금계산서 미발행 | 369 | **92,574,600** |
| 합계 | 483 | **115,507,964** |

> 🔴 **미발행분 92,574,600원은 세무사 확인이 필요한 금액**입니다.
> 프로그램은 판단하지 않고 아래 뷰로 목록만 제공합니다.

### `v_vat_unbilled` — 부가세는 받았는데 세금계산서는 미발행 ⭐

```sql
CREATE VIEW v_vat_unbilled AS
SELECT o.id, o.order_no, p.name AS partner, r.receipt_date,
       s.amount_krw AS vat_received
FROM receipt_splits s
JOIN receipts r ON r.id = s.receipt_id
JOIN orders   o ON o.id = r.order_id
JOIN partners p ON p.id = o.partner_id
WHERE s.split_kind = 'VAT'
  AND o.invoice_status = 'NONE'          -- 세금계산서 미발행
  AND r.is_void = FALSE;
```

세금계산서 관리 화면에 `미발행 · 부가세 수취` 탭으로 노출하고, 대시보드에 건수·금액 배지를 답니다.

## 9. 무결성 제약 요약

| # | 제약 | 구현 |
|---|------|------|
| 1 | `SUM(receipt_splits) = receipts.amount` | DB 트리거 |
| 2 | `SUM(expense_allocations) ≤ expenses.amount` | DB 트리거 |
| 3 | `SUM(remittance_allocations) = remittances.krw_amount` | DB 트리거 |
| 4 | 예치금 잔액 < 0 차단 | 트랜잭션 검증 (매니저 승인 시 허용) |
| 5 | `deposit_ledger` UPDATE/DELETE 금지 | DB RULE |
| 6 | `SETTLED` 주문 하위 전표 수정 금지 | 애플리케이션 + 트리거 |
| 7 | 금액 필드 변경 시 사유 필수 | 애플리케이션 |
| 8 | **KRW↔CNY 환산 필요 시 환율 NULL 금지** | CHECK 제약 ⭐ |
| 9 | **`is_internal` 거래처는 매출 집계 제외** | 집계 뷰에서 필터 ⭐ |
| 10 | **주문 지출 > 입금이면 차액을 미수금으로 집계** | 계산 뷰 `v_receivables` ⭐ |
| 11 | **부가세는 회사 자금에서 차감** | 계산 뷰 `v_vat_payable` ⭐ |
